## session-report.html (작업 보고서, 8페이지)

### 기준별 점수 근거

**사용자 만족도 3.5.** 1페이지의 핵심 수치 3개(고친 파일 9개, 커밋 14개, 검사 612개 통과)와 7개 불릿 요약으로 무엇을 했는지는 바로 알 수 있다(`sr-1280-p1.png`). 그러나 8페이지 '남은 일'에서 사용자가 정할 사항 두 가지(원격 푸시 여부, 01~08 파일 삭제 또는 재생성)에 권장안이 없다(`sr-1280-p8.png`). 독자는 "그래서 어느 쪽을 하라는가"를 다시 물어야 한다.

**심미성 3.0.** 색은 절제되어 있고 표 서식은 리서치 노트 수준이다. 그러나 다음 결함이 있다.
- 용어 풀이 목록: 1페이지 요약 상자 바로 아래에 제목 없이 붙어 있고, 용어는 왼쪽 끝, 풀이는 화면 중앙 오른쪽(약 x=655)에 떨어져 있어 짝이 읽히지 않는다(`sr-1280-p1.png`, `sr-390-p1.png`).
- 페이지 번호 중복: 상단 내비게이션의 `1 / 8` 과 본문 첫 줄의 `1 / 8` 이 같은 화면에 두 번 보인다(모든 페이지).
- 세로 흐름도: 2페이지의 9단계 직선 흐름도가 화면 중앙에 좁게 늘어서 약 800px 를 차지하지만, 바로 아래 '단계별 결과' 표와 정보가 같다(`sr-1280-p2.png`).
- 모바일 표: 6페이지 4열 표가 390 폭에서 첫 열이 폭을 독차지하고 '변경 전' 열이 글자 1~2개 폭으로 잘린다. 가로 스크롤 단서도 없다(`sr-390-p6.png`). 표 실제 폭은 626px, 화면은 343px 이다.

**구성의 조직성 3.5.** 페이지마다 결론 불릿 → 근거 → 중요 포인트 → 유의사항 → 출처 순서가 일관된다. 다만 3페이지 '바뀐 규칙'은 변경 후 표만 있고 변경 전 배정표가 없어서 제목이 약속한 비교가 성립하지 않는다(`sr-1280-p3.png`). 8페이지 표의 '단일 문구 검사' 행은 이미 끝난 일(필요한 결정: 없음)인데 '남은 일'에 들어 있다.

**이해 용이성 3.0.** 1페이지 용어 풀이는 렌즈·호출자·e4만 다룬다. 본문에 반복해 나오는 L1, L2, 음성 시험(4·7페이지), 차수, fast-forward, 워크트리는 풀이가 없다(`sr-1280-p4.png`, `sr-1280-p6.png`, `sr-1280-p7.png`).

**논리 전개 3.0.** 본문 제목이 모두 명사구('작업 흐름', '바뀐 규칙', '남은 일')라서 제목만 읽으면 논지가 보이지 않는다. 결론 문장은 제목 아래 불릿에 있다. 7페이지 첫 불릿은 "검사 실패 3가지와 규칙 소실 1가지"라고 적지만, 표에는 plan 리뷰 행이 3개이고 어느 행이 규칙 소실인지 표시가 없다(`sr-1280-p7.png`).

### 상위 결함

- **결정 권장안 누락 (8페이지):** 필요한 결정 두 건에 권장안과 근거가 없다. 고칠 방향: '필요한 결정' 열 옆에 '권장안' 열을 추가한다.
- **용어 풀이 배치 (1페이지):** 제목 없는 정의 목록이 요약 상자에 붙고 용어와 풀이가 멀리 떨어진다. 고칠 방향: '용어' 절 제목을 두고 2열 격자를 좁게(용어 열 8~10em) 잡는다.
- **모바일 표 붕괴 (5·6페이지):** 4열 표의 열이 1~2글자 폭으로 잘린다. 고칠 방향: 390 폭에서는 행을 카드형 정의 목록으로 바꾸거나 첫 열 최소 폭과 스크롤 그림자를 둔다.
- **중복 흐름도 (2페이지):** 9단계 흐름도와 표가 같은 정보를 반복한다. 고칠 방향: 흐름도를 가로 한 줄 단계 막대로 줄이거나 삭제하고 표만 남긴다.
- **변경 전 부재 (3페이지):** '바뀐 규칙'에 이전 규칙이 없다. 고칠 방향: 이전 배정표 4종과 새 그룹표를 나란히 둔 대조표를 넣는다.
- **해시 이동 미동작:** 같은 탭에서 주소의 `#p2` 만 바꾸면 페이지가 넘어가지 않는다(`hashchange` 처리 없음, 실측). 고칠 방향: 페이지 전환 스크립트에 `hashchange` 수신을 추가한다.

## 04-rules.html (검토 자료, 3페이지, 애니메이션 `d-flow` 포함)

요청서는 2페이지라고 적었으나 실측 결과 3페이지(요약, 제안과 승인의 흐름, 호출자별 제안 시점)이다.

### 기준별 점수 근거

**사용자 만족도 2.5.** 3페이지 표는 review-specs가 "리뷰 결과를 전달할 때" 선행연구를 제안한다고 적는다(`r04-1280-p3.png`). 그러나 session-report 6페이지는 이 시점이 "렌즈 실행 전 준비 단계"로 바뀌었다고 보고한다(`sr-1280-p6.png`). session-report 8페이지도 01~08 파일이 옛 spec 기준이라고 인정한다. 그런데 04-rules 본문에는 superseded 표시가 없다. 이 문서만 받은 독자는 옛 규칙으로 결정하게 된다.

**심미성 2.5.** 1페이지에 session-report와 같은 용어 풀이 배치 결함이 있다(`r04-1280-p1.png`). 2페이지 Mermaid 흐름도는 높이가 1149px 로 1280×800 화면 하나를 넘는다(`r04-1280-p2-start.png`). '예' 연결선이 오른쪽 끝을 따라 길게 내려가고, '아니오' 선이 다른 선과 교차한다. 강조는 노드 테두리를 1px 에서 2px 남색으로 바꾸는 방식뿐이고 지나온 경로의 연결선은 강조되지 않는다(`r04-1280-p2-step08-viewport.png`, `r04-1280-p2-step19-fig.png`). 현재 노드와 지나온 노드가 같은 모양이라 어디에 있는지 구분이 어렵다. 거절 노드만 적색 테두리이다. 390 폭에서는 흐름도가 343px 로 축소되어 노드 글자가 약 9px 로 보인다(`r04-390-p2.png`).

**구성의 조직성 3.0.** 요약 → 흐름 → 호출자별 시점의 순서는 독자의 질문 순서와 맞다. 그러나 2페이지 '공통 규칙' 표가 위 흐름도 및 결론 불릿과 같은 내용을 세 번째로 반복한다.

**이해 용이성 2.0.** 애니메이션이 이해를 방해한다.
- 재생 속도: 28단계가 8.7초에 끝나고 단계마다 0.32초만 머문다. 자막 한 문장(예: "시나리오 D · 승인: 사용자가 거절합니다.")을 읽기 전에 다음 문장으로 바뀐다.
- 화면 배치: 자막과 조작 버튼이 1149px 흐름도 아래에 있어서, 흐름도 위쪽 노드가 강조될 때 자막은 화면 밖에 있다(`r04-1280-p2-step08-viewport.png`). 강조와 설명을 동시에 볼 수 없다.
- 반복 단계: 시나리오 B~E가 매번 "직접 요청이 없습니다", "메인 세션이 실행합니다"를 따로 한 단계씩 반복해 28단계 중 8단계가 같은 말이다.
- 용어: L1, 봉인, 발동 기준이 풀이 없이 나온다(1페이지는 L2와 차수만 풀이한다).

**논리 전개 3.0.** 2페이지 결론 불릿 4개는 흐름도 분기와 일대일로 대응한다. 1페이지 핵심 수치 'readability 발동 기준 1개'는 값이 달라져도 결정이 바뀌지 않는 숫자이다. 본문 제목은 명사구이다.

### 상위 결함

- **옛 규칙 표시 누락 (3페이지):** review-specs 제안 시점이 현행과 다른데 표시가 없다. 고칠 방향: 문서 머리에 superseded 배너와 현행 문서 링크를 넣거나 현행 규칙으로 재생성한다.
- **단계당 0.32초 재생 (2페이지):** 자막만 있는 단계에 읽기 시간이 주어지지 않는다. 고칠 방향: 엔진에서 하단 자막 글자 수로도 머무는 시간을 계산한다(공통 패턴의 엔진 결함 참조).
- **강조와 자막의 분리 (2페이지):** 흐름도가 한 화면을 넘어 강조 노드와 자막을 함께 볼 수 없다. 고칠 방향: 흐름도 최대 높이를 화면 높이의 70%로 제한하거나 가로 방향(LR)으로 그리고, 자막을 흐름도 위나 강조 노드 옆에 둔다.
- **약한 강조 (2페이지):** 현재 노드와 지나온 노드가 같은 2px 테두리이다. 고칠 방향: 현재 노드는 채움색으로, 지나온 경로는 연결선 색으로 구분한다.
- **반복 단계 (2페이지):** 5개 시나리오가 공통 앞단계를 반복한다. 고칠 방향: 시나리오마다 분기점 1~2단계만 연출하고 공통 경로는 한 단계로 묶어 28단계를 12단계 이하로 줄인다.

## 03-groups.html (검토 자료, 4페이지, 정적 도식)

### 기준별 점수 근거

**사용자 만족도 3.0.** 그룹 3개와 렌즈 6개의 소속은 2페이지 표 하나로 알 수 있다(`g03-1280-p2.png`). 다만 이 문서도 session-report 8페이지가 옛 spec 기준이라고 지목한 01~08 묶음에 속하는데 superseded 표시가 없다. 1페이지 핵심 수치 'review-specs 호출 수: 변화 없음'은 기준값이 없어 무엇과 같다는 뜻인지 알 수 없다(`g03-1280-p1.png`).

**심미성 3.0.** 2페이지 도식의 세 그룹 상자는 폭과 가로 위치가 제각각이다. '대상 문서 하나', '전체 입력', '사용자 승인' 입력 상자도 왼쪽 정렬이 맞지 않는다(`g03-1280-p2.png`). grounding과 fit을 잇는 세로선에 이름표가 없어 '함께 둔다'는 뜻이 그림에서 읽히지 않는다. 390 폭에서는 도식 글자가 약 6px 로 줄어 읽을 수 없다(`g03-390-p2.png`). 2페이지 5열 표는 390 폭에서 '실행하는 호출자' 열이 한 줄에 단어 하나씩 끊긴다.

**구성의 조직성 3.5.** 그룹 구성 → 호출자별 입력 → 예외 목록 이관 순서는 자연스럽다. 2페이지에서 결론 불릿, 도식, 표가 같은 세 가지 사실(그룹 3개, 함께 두는 렌즈 2개, 나머지 단독)을 세 번 반복한다.

**이해 용이성 3.0.** 표의 '자세' 열(대조·공격·생성·외부 탐색)은 풀이가 없다. '턴', '컨텍스트', '포인터', '짝 문서'도 풀이 없이 나온다(`g03-1280-p2.png`, `g03-1280-p3.png`, `g03-1280-p4.png`). 용어 풀이는 전체 입력과 L2 두 개뿐이다.

**논리 전개 3.0.** 2페이지 세 번째 불릿은 "adversarial과 필요할 때 그룹의 렌즈는 어느 렌즈와도 컨텍스트를 나누지 않는다"고 적는다. 그러나 표에서는 lens-consistency도 '함께 두는 렌즈: 없음'이므로 불릿이 consistency를 빠뜨렸다. 3페이지 세 번째 불릿 "에이전트 상한 10개 안에 센다"는 같은 페이지 표와 출처 어디에도 근거가 없다(`g03-1280-p3.png`).

### 상위 결함

- **불릿과 표의 불일치 (2페이지):** 단독 렌즈 목록에서 consistency가 빠졌다. 고칠 방향: "grounding·fit 외 4개 렌즈는"으로 고친다.
- **근거 없는 주장 (3페이지):** 에이전트 상한 10개의 출처가 없다. 고칠 방향: 상한을 정한 문서와 절을 출처에 추가하거나 불릿을 삭제한다.
- **도식 정렬과 모바일 판독성 (2페이지):** 상자 정렬이 맞지 않고 390 폭 글자가 6px 이다. 고칠 방향: 세 그룹을 같은 폭의 가로 3열 격자로 그리고, 모바일에서는 도식 대신 표만 보이거나 최소 글자 크기를 보장한다.
- **'변화 없음' 핵심 수치 (1페이지):** 비교 기준이 없다. 고칠 방향: "review-specs 호출 수 N회(변경 전과 같음)"처럼 수치를 적는다.
- **옛 spec 표시 누락:** 고칠 방향: 04-rules와 같이 superseded 배너를 둔다.

## tests/sample-anim.html (스킬 견본, 3페이지, 애니메이션 2개)

### 기준별 점수 근거

**사용자 만족도 3.0.** 1페이지 핵심 수치(모델 A 비중 50% → 31%, 손절 효과 −16bp)와 요약 두 줄로 결론은 바로 보인다(`sa-1280-p1.png`). 그러나 견본이므로 스킬 사용자가 이 결과를 따라 하게 되며, 아래 결함이 그대로 복제된다.

**심미성 3.0.** 캐릭터 그림은 선이 깔끔하고 과하지 않다. 다음 결함이 있다.
- 설명 상자: 한 줄 글에 비해 상자가 세 줄 높이라 빈 공간이 크다(`sa-1280-p2-start.png`). 4단계 상자는 "손해"만 둘째 줄로 넘어간다(`sa-1280-p3-step4-end.png`).
- 막대 수치: 수치 라벨(31%, 25%)이 막대 끝이 아니라 오른쪽 고정 열(x≈870)에 있어 막대와 떨어진다.
- 축 부재: 누적 손익 선 그래프에 월 눈금과 y축이 없다. 0 기준선 하나만 있어서 "4개월째", "고점 15"를 그림에서 확인할 수 없다(`sa-1280-p3-step2.png`).
- 잔여 표식: 1단계 화면 오른쪽 끝(약 x=958, y=580)에 작은 점 하나가 남아 있다(`sa-1280-p3-step1.png`).
- 모바일 판독성: 390 폭에서 설명 상자 글자가 약 5px 로 줄어 읽을 수 없다(`sa-390-p3-step2.png`).

**구성의 조직성 3.5.** 요약 → 전후 전환 → 규칙 재생 순서와 페이지 내부 구조는 일관된다. 목차의 ★와 ☆ 기호는 뜻이 설명되지 않는다.

**이해 용이성 3.0.** 단계당 2.1~2.9초 머물러 읽을 수는 있다. 그러나 다음 결함이 이해를 방해한다.
- 1단계 생략: 재생 시작 9~10ms 만에 2단계로 넘어가 1단계(모델 A 비중 축소, 규칙 없음 선 그리기) 연출이 보이지 않는다.
- 기준선 소실: 전후 전환의 마지막 화면에서 세 막대가 모두 남색이 된다(`sa-1280-p2-step3-end.png`). 그림 설명은 "회색은 기준선"이라고 하지만 회색 막대가 사라져 전과 후를 비교할 수 없다. 모델 A의 원래 50%는 어느 단계에서도 막대로 남지 않는다.
- 이중 설명: 설명 상자("모델 B: 거의 그대로")와 하단 자막("모델 B: 다른 모델과 따로 움직여…")이 같은 내용을 다른 문장으로 두 번 말한다. 2단계 진입 직후 약 130ms 동안은 자막이 2단계인데 설명 상자는 1단계 글을 보인다.
- 캐릭터 위치: 캐릭터와 설명 상자가 그래프 위 고정 위치에 있어서 사건 지점(손절 발동 점, 해당 막대)을 가리키지 않는다. 2단계 중간에는 캐릭터가 사라졌다 다시 나온다(`sa-1280-p2-step2-mid.png`).

**논리 전개 3.0.** 결론 불릿의 수치(38bp → 22bp, 16bp)는 표 및 4단계 화면과 일치한다. 그러나 2단계 설명 상자는 "고점 15 → −2bp"로 17bp 하락을 보이고, 자막과 결론 불릿은 "고점 대비 10bp 넘게"라고 적어 기준이 두 가지로 읽힌다. 표의 4개월째 값은 두 행 모두 −2라서 규칙 발동 시점의 차이를 보여 주지 못한다.

### 상위 결함

- **1단계 생략:** 연속 재생에서 1단계가 연출되지 않는다. 고칠 방향: 엔진 `play()` 가 처음 상태에서 시작할 때 `e0` 끝이 아니라 타임라인 0초부터 재생하게 한다.
- **전후 비교 소실 (2페이지):** 끝 화면에 기준선 막대가 없다. 고칠 방향: 기준선 막대를 옅은 회색으로 남기고 제안안 막대를 그 위에 겹친다.
- **축 없는 선 그래프 (3페이지):** 월과 bp 눈금이 없다. 고칠 방향: x축 월 눈금 10개와 y축 눈금 3~4개를 넣고, 손절 발동 점에 "4개월째" 라벨을 붙인다.
- **설명 이중화:** 상자와 자막이 같은 말을 반복한다. 고칠 방향: 도형 옆 설명 상자 하나로 통일하고 하단 자막은 단계 번호와 제목만 둔다.
- **모바일 글자 축소:** SVG 전체 축소로 글자가 5px 이 된다. 고칠 방향: 390 폭에서는 설명 상자를 SVG 밖 HTML 로 옮기거나 최소 글자 크기를 보장한다.

## 네 문서의 공통 결함 패턴

아래 결함은 개별 문서가 아니라 스킬 규칙이나 엔진(`report-charts` 스크립트, 페이지 틀)을 고쳐야 없어진다.

- **엔진: 1단계 생략.** `play()` 는 `cur === last` 일 때만 `go(0)` 으로 되돌리고, 그 밖에는 이미 `e0` 끝으로 이동한 타임라인을 재생한다. 그래서 세 애니메이션 모두 시작 9~12ms 만에 2단계가 된다. 고칠 방향: '처음부터' 상태에서 재생하면 `tl.seek(0)` 뒤 재생하고, 시험(`RC.check`)에 "1단계 체류 시간 > 0" 항목을 추가한다.
- **엔진: 자막 전용 단계에 읽기 시간 없음.** `holds[i]` 는 SVG 안 글 등장(`beats`)이 있을 때만 계산된다. Mermaid 애니메이션처럼 하단 자막만 있는 단계는 머무는 시간이 0이 되어 단계당 0.32초가 된다(04-rules). 고칠 방향: 자막(`step.text`) 글자 수로도 `holdFor` 를 계산하고, 단계당 최소 1.5초를 강제하는 검사를 둔다.
- **엔진: 설명 위치 이원화.** 설명 상자와 하단 자막이 같은 내용을 두 번 말하고, Mermaid 모드는 하단 자막만 쓴다. 긴 도형에서는 자막이 화면 밖에 있다. 고칠 방향: 스킬 규칙에서 설명 위치를 한 곳(강조 대상 옆)으로 정하고, 도형 높이가 화면 높이를 넘으면 자막을 도형 위에 고정한다.
- **엔진: 모바일 SVG 일괄 축소.** 모든 SVG 도식이 `viewBox` 비율대로 축소되어 390 폭에서 글자가 5~9px 가 된다(`r04-390-p2.png`, `g03-390-p2.png`, `sa-390-p3-step2.png`). 고칠 방향: 렌더 후 실제 글자 높이가 11px 미만이면 도식을 가로 스크롤 상자에 넣거나 세로 배치로 다시 그리는 규칙을 둔다. 완료 검사에 최소 글자 크기 항목도 추가한다.
- **페이지 틀: 용어 풀이 목록 배치.** 세 문서(session-report, 04-rules, 03-groups)에서 정의 목록이 제목 없이 요약 상자에 붙고, 용어와 풀이 열이 화면 양 끝으로 떨어진다. 고칠 방향: 틀의 `dl` 스타일을 용어 열 고정 폭 2열 격자로 바꾸고 '용어' 소제목을 자동으로 넣는다.
- **페이지 틀: 페이지 번호 중복과 해시 이동.** 상단 내비게이션과 본문 첫 줄에 같은 페이지 번호가 두 번 나온다. 주소의 해시만 바꾸면 페이지가 넘어가지 않는다. 고칠 방향: 본문 `pno` 는 인쇄 때만 보이게 하고 `hashchange` 를 처리한다.
- **스킬 규칙: 본문 제목이 명사구.** 네 문서 모두 페이지 제목이 '작업 흐름', '그룹별 렌즈' 같은 명사구이고 결론은 아래 불릿에 있다. 제목만 읽어서는 논지가 이어지지 않는다. 고칠 방향: 페이지 제목 위 작은 절 이름(목차)과 결론 한 문장 제목(40자 이하, 수치 포함)의 두 층을 틀의 기본으로 둔다.
- **스킬 규칙: 같은 사실의 삼중 반복.** 결론 불릿, 도식, 표가 같은 사실을 반복하는 페이지가 많다(sr 2페이지, r04 2페이지, g03 2페이지). 고칠 방향: 도식은 표가 보여 줄 수 없는 관계(분기, 흐름, 변화)가 있을 때만 넣는다는 규칙을 추가하고, 도식과 표의 항목이 80% 이상 겹치면 하나를 빼게 한다.
- **스킬 규칙: 용어 풀이 범위 부족.** 각 문서가 2~3개 용어만 풀고 L1, 음성 시험, 봉인, 자세, 턴 같은 저장소 전용 용어는 남긴다. 고칠 방향: 완료 검사에서 본문의 영문 약어와 따옴표 용어를 추출해 풀이 목록과 대조한다.
- **스킬 규칙: 옛 기준 문서 표시.** 01~08 검토 자료가 현행과 다른 규칙을 포함하고 있으나 문서 안에 표시가 없다. 고칠 방향: 재빌드하지 않은 기존 문서에는 머리 배너(superseded, 현행 문서 링크)를 넣는 규칙을 스킬의 기존 문서 안내에 추가한다.
- **스킬 규칙: 모바일 다열 표.** 4~5열 표가 390 폭에서 열이 1~2글자 폭으로 잘린다. 고칠 방향: 열이 4개 이상이면 좁은 화면에서 행 단위 정의 목록으로 바꾸는 CSS 를 틀에 넣는다.

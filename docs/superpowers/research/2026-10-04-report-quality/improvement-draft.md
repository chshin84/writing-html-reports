# HTML 보고서 스킬 개선안 초안 (선행연구 대조용)

## 배경

LLM 코딩 에이전트가 프로젝트를 마무리할 때 사용자가 결과를 확인하도록 HTML 보고서를 만드는 스킬이 있다. 보고서는 페이지 단위로 넘겨 보고, 차트·도식·단계형 애니메이션을 포함한다. 사용자는 금융업 종사자이고 본인 화면에서 검토한다.

## 관찰한 사용 기록

- 작업 보고서를 받은 직후 사용자가 "시나리오 10개로 무엇이 바뀌었는지 설명해 달라", "남은 것이 있나", "미룬 보강을 진행하라"를 차례로 요청했다. 보고서에 변경 전후 사례와 남은 항목이 없었다.
- 보고서를 원격 기기(모바일)에서 볼 수 있게 올려 달라는 요청이 두 세션에서 반복되었다.
- 보고서 작성 전 요약 결론 승인 단계에서, 사용자는 "이대로 보고서 작성" 대신 "결정 사항 먼저 처리"를 골랐다. 점검에서 나온 미결정 사항이 보고서 내용을 바꾸기 때문이다.
- 분기 흐름도 애니메이션(분기마다 시나리오 하나, 총 약 28단계)에서 단계마다 노드 테두리만 0.3초 바뀌고 넘어가서 너무 빠르다. 설명 문장은 도형 옆이 아니라 그림 아래 자막 줄에 나온다. 안내 캐릭터(스틱맨)가 나오지 않는다.

## 개선안

- **A1 단계 최소 체류 시간:** 무대 안 글이 없는 단계에도 자막 글자 수에 비례한 체류 시간(1초 + 글자 수 ÷ 10초, 상한 4초)을 준다. 연속 재생은 단계마다 멈춰 읽을 시간을 준다.
- **A2 설명을 도형 옆으로:** Mermaid로 그린 흐름도에서도 현재 노드 옆에 설명 상자를 두고, 그림 아래 자막 줄은 접근성용 목록으로만 남긴다.
- **A3 안내 캐릭터:** Mermaid 흐름도에서도 스틱맨(안내·고민·통과·실패 네 가지)을 설명 상자와 한 쌍으로 노드 옆에 둔다. 판단 노드에서는 고민 → 판정 전환을 보여 준다.
- **A4 긴 시나리오 분할:** 단계가 많으면(예: 12단계 초과) 시나리오 선택 버튼으로 나눠 한 번에 한 시나리오만 재생한다.
- **B1 작업 보고서 유형:** 마무리 보고서에 '바뀐 것(변경 전후 사례 표)', '남은 항목(미푸시 커밋, 남은 폴더·브랜치, 미룬 보강, 사용자 결정 대기)'을 필수 절로 둔다.
- **B2 결정 먼저:** 요약 결론 승인 단계에서 미결정 사항이 나오면 보고서를 쓰기 전에 하나씩 결정받고, 보고서는 결정 뒤의 상태를 설명한다.
- **B3 원격 게시:** 완성한 보고서를 원격에서 열 수 있는 비공개 페이지로 게시하는 단계를 기본 절차에 넣는다.

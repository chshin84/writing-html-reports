# C1 애니메이션 엔진 spec 리뷰 기록

검토 대상은 `docs/superpowers/specs/2026-10-04-c1-animation-engine-design.md`이고, 렌즈별 원본은 같은 이름의 폴더에 있다.

## 실행 개요

렌즈는 lens-grounding, lens-consistency, lens-adversarial, lens-fit을 읽기 전용 에이전트로 따로 실행했다. 렌즈를 한 번씩만 실행했다. 선행연구 렌즈는 붙이지 않았다. 이 spec은 상위 설계가 정한 엔진 개선을 구현하는 컴포넌트 설계이고, 근거가 된 선행연구 대조는 같은 날 마쳤다.

## 병합한 지적

- **현재 노드를 알 수 없는 견본:** sample-viz의 Mermaid 애니메이션은 문서 쪽 함수로, sample-anim은 강조 함수 없이 요소를 직접 바꾼다. mark·spot 계기로는 현재 노드와 설명 상자가 생기지 않는다. sample-anim은 설명 상자 좌표를 호출 코드에 고정했다. (grounding, consistency 공동)
- **단계 넘김과 타임라인 계약:** 단계 끝 라벨이 머무는 시간을 포함해 단계 넘김이 멈출 지점이 없다. 두 방식의 버튼 동작 차이가 정의되지 않았다. (consistency, adversarial 공동)
- **n의 정의:** 엔진의 n과 측정 도구의 n이 다르다. (consistency)
- **자동 설명 상자:** 단계 문장 전체를 넣으면 30자 규칙과 충돌한다. 직접 그린 무대의 기존 설명 상자와 겹칠 수 있다. 자리가 없을 때 처리와 회피 대상(.rc-note·.rc-icon), 클래스 요구가 없다. (adversarial, consistency)
- **시나리오 묶기:** 'X · Y' 모양만으로 묶으면 다른 뜻의 이름을 묶는다. 선택 버튼이 조작 버튼 순서를 깨뜨릴 수 있다. 이어 재생 규칙과 RC.check 범위, 단일 타임라인 여부가 없다. 선택 UI가 과설계라는 지적도 있었다. (adversarial, consistency)
- **스틱맨:** 실패·완료 규칙이 판단 노드로 한정되지 않아 끝 노드와 직접 그린 무대에서 중복된다. 상위 설계의 '통과'와 다르다. 위치 선택에 스틱맨 자리가 없다. 고민과 실패가 같은 단계에 함께 걸린다. (adversarial, consistency, grounding)
- **화면 안 유지:** 문서 열기·인쇄 복원·자동 재생에서도 스크롤이 일어나 사용자 스크롤을 빼앗는다. (adversarial)
- **390px 글자:** 숨은 페이지의 폭 0 계산과 인쇄 처리가 없다. (adversarial)
- **간선 강조:** 상위 설계에 없고 간선 id 형식에 기댄다. (adversarial)
- **기존 규칙의 처분:** 4초 상한·30자 상한·1초 글 등장의 처분이 없다. '정지 상태는 마지막 장면'은 현재 동작과 다르다. (adversarial, grounding)
- **견본 결함의 성격:** 기준선 막대와 축은 견본 코드 수정이고 고정 견본 판정에 반영되지 않는다. (grounding)
- **판정 범위 누락:** 보류 견본, 그림 질문, 하락 금지, 판정 차례가 빠졌다. 호출 코드를 고쳐야 할 때의 BLOCKED, plan 위치와 마커, 소유 견본 재빌드, RULES 짝 규칙이 없다. 자가 점검 '3회'가 두 뜻이다. (consistency)
- **시험 범위:** 시험 대상이 두 가지로 읽히고, 발동하지 않아야 하는 입력의 시험이 없다. '옅은 채움'에 기준이 없다. (fit, adversarial)
- **근거 표현:** 스틱맨 근거를 research보다 강하게 단정했다. (grounding)
- **문체와 용어:** 개수 예고, 내부 이름 미풀이, 검증 절 첫 문장, 말끝, 여러 문장 불릿, 중간 관형절, 수식어 겹침. (fit)

## 걸러 낸 지적

- **시나리오 선택 UI가 어느 고정 견본에서도 발동하지 않는다는 지적:** 04-rules는 묶음 5개, 28단계라 발동 조건을 충족한다(grounding 확인). 과설계 지적은 근거가 틀려 거르고, 버튼 순서와 범위 지적만 남긴다.

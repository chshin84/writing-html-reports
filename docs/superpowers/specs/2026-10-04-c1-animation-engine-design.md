# C1 애니메이션 엔진 설계

작성일 2026-10-04. 상위 설계는 `docs/superpowers/specs/2026-10-04-report-quality-architecture-design.md`이고, 측정 도구(C0 하네스) 설계는 `docs/superpowers/specs/2026-10-04-c0-eval-harness-design.md`다.

## 목적과 범위

C1은 애니메이션·도식·차트를 그리는 엔진(`report-charts.js`)을 고친다. 목표는 고정 견본의 호출 코드를 바꾸지 않고도 단계가 읽을 시간만큼 머물고, 설명이 도형 옆에 나오는 것이다. 상위 설계와 이 문서가 다르면 상위 설계를 따르고, 다르게 정한 점은 리포트에 적는다.

이 문서가 쓰는 이름은 다음과 같다.

- **L1:** 메인 세션이다. 공식 측정·기본 방식 결정·병합을 맡는다.
- **L2:** C1을 맡는 서브오케스트레이터다. 이 문서의 독자이고, 사용자와 대화하지 못한다.
- **BLOCKED:** L2가 사용자나 L1의 결정이 필요할 때 작업을 멈추고 질문과 함께 돌려주는 상태다.
- **C0 하네스:** 다른 컴포넌트를 판정하는 측정 도구다. `eval/gates.py`(기계 판정), `eval/shoot.py`(장면), `eval/checklist.md`(체크리스트)가 있다.
- **고정 견본:** 호출 코드까지 고정한 HTML 사본이다(`bench/fixed/`). `eval/rebuild.py`가 현재 워크트리의 엔진을 넣어 다시 빌드한다.
- **단계 문장:** `RC.demo`의 단계 항목 `{name, text, play}`에서 `name`과 `text`다.
- **현재 노드:** 그 단계에서 연출하는 도형이다. 엔진이 `data-rc-active` 속성을 단다.

소유 파일은 다음과 같다. 그 밖의 파일은 읽기만 하고, 고쳐야 하면 BLOCKED로 돌려준다.

- **엔진과 스타일:** `report-charts.js`, `report-demo.css`, `report-peeps.js`, `tools/build-peeps.py`
- **규칙과 문서:** `checks/anim.py`, `시각화.md`
- **견본과 시험:** `tests/sample-anim.html`, `tests/sample-viz.html`, `tests/test_anim.py`, `tests/test_peeps.py`
- **작업 기록:** `docs/superpowers/plans/2026-10-04-c1-animation-engine.md`와 그 리뷰 기록

## 재생 방식

엔진은 자동 재생과 단계 넘김을 모두 두고, 문서를 열 때 고른 방식에 맞춰 타임라인을 만든다. 두 방식 모두 조작 버튼 네 개(이전·재생·다음·처음부터)를 같은 순서로 두고, 처음 누른 버튼이 1단계 연출부터 보이게 한다.

| 방식 | 타임라인 | '다음' | '재생' |
|---|---|---|---|
| 자동 재생(`auto`) | 단계 연출과 머무는 시간을 함께 넣는다 | 한 단계를 머무는 시간까지 재생한다 | 끝까지 이어서 재생한다 |
| 단계 넘김(`step`) | 단계 연출만 넣는다(단계마다 0.4~2.5초) | 한 단계의 연출만 재생하고 멈춘다 | 단계 사이에 체류 시간 규칙만큼 쉬며 이어서 재생한다 |

방식은 주소의 `?rc-mode=auto|step`으로 고르고, 인자가 없으면 `report-charts.js`의 기본값 상수를 쓴다. 처음 기본값은 `step`이다. 선행연구에서 사용자가 단계를 넘기는 방식의 이해도가 더 높았기 때문이다(`docs/superpowers/research/2026-10-04-report-quality/lens-prior-art-A.md`). L1이 실측 뒤 기본값을 바꿀 수 있다. figure에는 쓰는 방식을 `data-rc-mode`로 단다.

단계의 타임라인 구간은 라벨로 표시한다. 단계 i의 끝 라벨 `e(i)`는 자동 재생에서 머무는 시간까지, 단계 넘김에서 연출 끝까지를 포함한다. C0 하네스는 자동 재생의 타임라인을 0.05초 간격으로 옮기며 체류 시간을 잰다. 따라서 자동 재생의 머무는 시간을 `gsap.delayedCall` 같은 타임라인 밖 타이머로 만들지 않는다. 단계 넘김의 '재생'이 단계 사이에 쉬는 시간은 측정 대상이 아니므로 타이머로 만들어도 된다.

처음 연 상태의 타임라인 시간은 0이다. 인쇄에서는 지금처럼 마지막 장면을 보인다. GSAP이 없어 애니메이션을 만들지 못하면 지금처럼 단계 목록(`.demo-steps`)을 보인다.

## 체류 시간

자동 재생에서 각 단계는 글이 다 나온 뒤 1초 + n÷8초 이상, 그 값 + 3초 이하로 머문다. n은 그 단계에서 figure 안에 새로 보이는 글의 글자 수다. 단계 문장 자막, 설명 상자 글, 숫자 칸을 모두 세고, 공백은 빼며 숫자 묶음은 1자로 센다. 이 정의는 C0 하네스의 n과 같다. 무대 안 글이 없는 단계도 자막으로 n을 얻는다.

기존 규칙 가운데 표시 시간 규칙(`holdFor`, 최대 4초)만 이 식으로 바꾼다. 글 한 덩어리를 1초 안에 등장시키는 규칙과, 작성자가 쓰는 설명 상자 글 30자 상한은 그대로 둔다. `시각화.md`의 표시 시간 문장도 이 식으로 고친다.

## 시나리오 묶기

이름이 '시나리오 '로 시작하고 'X · Y' 모양인 단계는 X로 묶는다. 묶음은 단계 표시와 시나리오 선택에 쓰고, 타임라인은 하나로 유지한다.

- **타임라인:** 모든 단계를 한 타임라인에 차례로 두고, 라벨 `e(i)`는 전체 순번으로 매긴다. '재생'은 지금처럼 모든 시나리오를 이어서 재생한다.
- **단계 표시:** 묶음이 있으면 단계 표시를 '시나리오 A 2/4'처럼 시나리오 안의 순번으로 보인다.
- **시나리오 선택:** 묶음이 둘 이상이고 단계가 12개를 넘으면 조작 줄 아래에 별도 줄(`.demo-scen`)을 두고, 시나리오 버튼과 '전체' 버튼을 둔다. 시나리오를 고르면 그 시나리오의 첫 단계로 옮기고, 그 시나리오의 끝에서 재생을 멈춘다. '전체'가 처음 상태다.
- **조작 줄 보존:** 시나리오 버튼은 `.demo-ctl` 밖에 둔다. `.demo-ctl button`은 이전·재생·다음·처음부터 네 개를 이 순서로 유지한다. 재생이 끝나면 재생 버튼의 글을 '재생'으로 되돌린다. C0 하네스와 `RC.check`가 이 순서와 글로 버튼을 찾는다.

## 현재 노드와 설명 상자

엔진은 단계마다 현재 노드를 정해 표시하고, 작성자가 설명 상자를 쓰지 않은 figure에서는 설명 상자를 자동으로 둔다.

현재 노드는 그 단계의 `play(tl, $)` 안에서 `$`로 마지막에 조회한 요소다. `RC.fx.mark`·`RC.fx.spot`이 받은 요소가 있으면 그 요소를 우선한다. `$`는 엔진이 넘기는 조회 함수라서, 문서가 강조를 `tl.to`로 직접 하는 견본에서도 호출 코드를 바꾸지 않고 현재 노드를 알 수 있다. 엔진은 단계 끝에서 현재 노드에 `data-rc-active`를 달고 앞 노드에서는 뗀다.

현재 노드는 강조색 2px 테두리와 강조색 채움(불투명도 0.08)으로 그리고, 지나온 노드는 보조 강조색 1.5px 테두리로 그린다. 이 표시는 엔진이 현재 노드를 정할 때 함께 적용하며, 작성자가 `tl.to`로 준 색은 덮어쓰지 않는다.

자동 설명 상자는 figure에서 `RC.note`를 한 번도 만들지 않았을 때만 둔다. 작성자가 만든 설명 상자는 호환을 위해 옮기지 않는다. 자동 상자의 규칙은 다음과 같다.

- **내용:** 단계의 `text`만 넣고 바로 보인다(타이핑 효과 없음). 작성자 글의 30자 규칙은 적용하지 않고, 상자 폭(220px)에서 줄을 바꾼다.
- **위치:** 상자와 스틱맨을 한 덩어리로 보고, 현재 노드 경계에서 48px 이내에 놓는다. 무대 요소(노드 도형·글자·간선·간선 이름표)와 겹치지 않고 SVG 표시 범위 안에 들어오는 쪽을 오른쪽·왼쪽·아래·위 순서로 고른다.
- **자리 없음:** 네 쪽 모두 자리가 없으면 자동 상자를 두지 않고 자막을 보인다.
- **클래스:** 자동 상자는 `g.rc-note`, 스틱맨은 `g.rc-icon`으로 만든다.
- **이중화 제거:** 단계에 설명 상자(자동이든 작성자 것이든)가 보이면 그림 아래 자막(`.demo-cap`)을 숨긴다.

작성자가 고정한 설명 상자가 현재 노드에서 48px보다 멀어 C0 하네스의 `note-near` 판정에 걸릴 수 있다. 이 상황은 BLOCKED로 올리지 않는다. 대신 figure 이름과 거리를 리포트에 적고, L1이 판정한다.

## 화면 안 유지

단계가 바뀐 뒤 현재 노드나 설명 상자가 창 밖에 있으면, 엔진이 가장 가까운 위치로 스크롤한다. 단, figure가 화면과 일부라도 겹칠 때만 한다. 문서를 열 때의 초기화와 인쇄 뒤 복원에서는 스크롤하지 않는다. 그래서 사용자가 다른 곳으로 스크롤해 figure가 화면 밖으로 나가면 끌려오지 않는다. 움직임 줄이기 설정이면 부드러운 이동 없이 즉시 옮긴다. 이 스크롤은 타임라인 갱신에서 단계가 바뀔 때 일어나야 한다. C0 하네스가 타임라인을 옮겨 가며 재기 때문이다.

## 스틱맨

자동 스틱맨은 Mermaid 마름모 노드의 판정 상태에만 둔다. 선행연구에서 성인 독자에게 캐릭터의 이해 효과는 근거가 약했고, 상태를 알리는 신호로 쓰는 쪽만 신호 원리의 지지를 받았기 때문이다(`lens-prior-art-A.md`).

- **고민:** 현재 노드가 마름모이면 설명 상자 옆에 고민하는 스틱맨(`person`)을 둔다.
- **판정:** 바로 앞 단계의 현재 노드가 마름모였으면, 이번 단계에서 그 마름모 옆의 스틱맨을 바꾼다. 이번 단계의 강조 색이 `neg`(거부·오류를 뜻하는 강조색 토큰)이면 `person-fail`, 아니면 `person-done`이다.
- **동시 발동:** 마름모가 `neg`로 강조되면 고민 스틱맨을 먼저 두고, 판정은 다음 단계에서 바꾼다.
- **적용 범위:** figure에서 `RC.icon`을 한 번도 만들지 않았을 때만 자동 스틱맨을 둔다. 직접 그린 무대의 작성자 아이콘과 겹치지 않게 하기 위해서다.
- **안내 제외:** 시나리오 첫 단계의 안내 스틱맨(`person-guide`)은 엔진이 자동으로 두지 않는다. `시각화.md`에서도 기본 사용을 뺀다.

## 도식과 차트

도식 SVG의 화면상 글자가 11px보다 작아지면, figure 안에 가로 스크롤 상자를 두고 SVG의 최소 폭을 글자가 11px이 되는 폭으로 정한다. 화면상 글자에는 SVG `text`와 `foreignObject` 안의 HTML 글자(Mermaid 노드 이름표, 설명 상자 글)가 모두 든다. 그림 폭이 0인 숨은 페이지에서는 계산하지 않고, 페이지가 보일 때와 창 크기가 바뀔 때 다시 계산한다. 인쇄에서는 스크롤 상자와 최소 폭을 풀어 페이지 폭에 맞춘다. 이 CSS는 `report-demo.css`에 둔다.

선 차트의 계열이 둘 이상이면 선 끝에 계열 이름을 직접 달고, 계열마다 다른 표식 모양을 쓴다. 색은 토큰 이름으로만 참조한다. 고정 견본에는 이 조건의 차트가 없으므로 단위 시험으로 확인한다.

## 소유 견본의 결함

`tests/sample-anim.html`의 두 결함은 엔진이 아니라 견본의 무대 SVG와 호출 코드를 고쳐서 없앤다. 첫째, 전후 전환의 끝 장면에서 기준선 막대가 사라진다. 둘째, 손익 선 그래프에 월과 bp(베이시스 포인트, 0.01%p) 축이 없다. 이 수정은 고정 견본(`bench/fixed/`의 사전 정리 직후 사본)의 판정에는 반영되지 않고, 스킬의 견본 품질만 높인다. 소유 견본의 호출 코드는 이 두 결함을 고치는 데만 바꾼다. 엔진 개선을 보이려고 견본 호출 코드를 바꾸지 않는다. 고정 견본의 호출 코드를 바꿔야만 개선되는 설계가 필요하면 BLOCKED로 돌려준다.

## 호환과 문서

기존 RC 함수의 인자는 그대로 동작해야 한다. 대상은 `RC.demo`, `RC.fx.*`, `RC.icon`, `RC.note`, `RC.focus`, `RC.check`, `RC.chart`이고, 새 기능은 선택 인자로만 추가한다. `RC.check`의 판정 규칙은 유지한다.

`checks/anim.py`에 규칙을 추가할 때는 `RULES` 목록에 규칙 함수와 원본 대조 방식을 짝지어 넣는다. 기존 규칙을 느슨하게 바꾸지 않는다. L1의 공식 측정은 기준 커밋의 규칙으로도 함께 검사한다.

`시각화.md`는 RC 함수 표, 표시 시간, 자동 설명 상자·스틱맨·시나리오 묶기, 재생 방식을 새 동작에 맞게 고친다. 엔진을 바꾼 뒤에는 소유 견본 두 파일에 `python build.py <파일>`을 실행해 관리 블록을 다시 채운다.

## 검증

L2는 아래 확인을 통과한 뒤 브랜치를 넘긴다. 병합 여부는 L1이 공식 측정으로 판정한다. 공식 측정은 L1만 가진 보류 견본도 쓰고, 그림 질문 정답률, 하락 금지, 판정 차례 3번 규칙을 적용한다. 그러므로 고정 견본에만 맞춘 분기(견본의 단계 수나 노드 이름에 기대는 코드)를 두지 않는다.

1. **기계 판정:** `python eval/rebuild.py <폴더>`로 고정 견본을 다시 빌드한다. 그 사본의 04-rules, 03-groups, sample-anim, sample-viz에서 아래 명령이 모두 통과한다.
   - `python eval/gates.py <html>… --only motion --mode auto`
   - `python eval/gates.py <html>… --only motion --mode step`

   작성자가 고정한 설명 상자의 `note-near` 실패만 예외로 리포트에 적는다.
2. **단위 시험:** `python -B -m unittest discover -s tests`가 통과한다. 시험은 아래 동작을 모두 덮는다.

## 함정

다음은 2026-10-04 실측과 코드 확인으로 얻은 사실이다.

- **자기 판정의 맹점:** `RC.check`는 겹침과 글 규칙만 보고, 체류 시간·1단계·설명 위치는 보지 않는다.
- **1단계 생략의 원인:** 시작할 때 `go(0, false)`가 타임라인을 `e0`으로 옮겨 둔다. 그래서 재생은 거기서부터 진행하고, '다음'은 2단계로 간다(`report-charts.js`의 `go` 함수와 초기화 호출).
- **체류 시간의 원인:** 머무는 시간은 무대 안 글 등장(`beats`)이 있을 때만 계산된다. 기존 상한 4초는 48자를 넘는 문장에서 한국어 자막 상한(초당 12자)을 넘는다.
- **이름표 구조:** Mermaid 노드 이름표는 SVG `text`가 아니라 `foreignObject` 안의 HTML이다. 04-rules 흐름도에서 390 폭의 화면상 크기는 약 9px다.
- **강조 방식이 다른 견본:** sample-viz의 Mermaid 애니메이션은 문서 쪽 함수가 `tl.to`로 노드 테두리를 바꾼다. sample-anim은 강조 함수 없이 `$`로 얻은 막대를 바꾸고, 설명 상자 좌표를 `RC.fx.pair` 인자로 고정한다.
- **페이지형 문서:** 숨은 페이지의 그림은 폭이 0이다. 페이지 넘김 막대에도 단계 표시와 같은 클래스(`.cnt`)의 번호가 있다.
- **설명 위치의 근거:** 그림과 설명을 가까이 두는 효과 크기는 g = 0.63이다. g는 두 집단의 평균 차이를 표준편차로 나눈 지표다. 이 근거는 동적 그림과 좁은 화면에서 약하므로, 위치는 측정으로 확인한다.

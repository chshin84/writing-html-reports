# C0 평가 하네스 설계

작성일 2026-10-04 · 상위 설계 `docs/superpowers/specs/2026-10-04-report-quality-architecture-design.md` · 기준 커밋 `512d308`

## 목적과 범위

C0은 보고서 품질 개선의 측정 도구, 고정 견본, 체크리스트, 개선 전 기준선을 만들고, 다른 컴포넌트는 이 도구로만 판정받는다. 상위 설계의 「측정 체계」, 「완료 기준」, 「인터페이스」의 평가 실행, 「평가 자료의 격리」를 이 컴포넌트가 구현한다. 상위 설계와 이 문서가 다르면 상위 설계를 따르고, 다른 점을 리포트에 적는다.

이 문서가 쓰는 이름은 다음과 같다.

- **L1:** 메인 세션이다. 공식 측정과 병합을 맡는다.
- **L2:** 컴포넌트 하나를 맡는 자율 서브오케스트레이터다. 이 문서의 독자는 C0의 L2다.
- **C1·C2·C3:** 애니메이션 엔진, 페이지 틀·CSS, 보고서 내용 규격 컴포넌트다. 이 하네스로 판정받는다.
- **엔진:** `report-charts.js`다. 관리 블록으로 문서에 들어가 차트·도식·애니메이션을 그린다. `RC.demo`·`RC.note`·`RC.icon`·`RC.fx`가 엔진의 애니메이션 함수다.
- **보류 자료:** L1만 보관하는 평가 자료다. 정답이 든 질문, 심을 오류의 정의, 보류 견본, 재생성 원자료가 여기에 든다.
- **적용 대상:** 판정 항목과 체크리스트 항목에 붙이는 표시다. `motion`은 C1, `layout`은 C2, `content`는 C3의 판정에 쓴다.

C0의 소유 파일은 `eval/**`, `bench/**`, `tests/test_eval_*.py`이고, 그 밖의 파일은 읽기만 한다. C0은 엔진·CSS·규칙 모듈을 고치지 않는다. 보류 자료는 만들지도 찾지도 않는다.

## 문서 열기

`eval/gates.py`와 `eval/shoot.py`는 문서를 같은 조건으로 연 뒤에만 측정하고, 열기에 실패하면 판정 대신 환경 실패를 돌려준다. 문서는 Python Playwright의 헤드리스 Chromium으로, `http.server`로 띄운 로컬 주소에서 연다.

측정은 다음 조건이 모두 갖춰진 뒤 시작한다.

- **글꼴:** `document.fonts.ready`가 끝났다.
- **애니메이션:** 원문에 `RC.demo` 호출이 있는 figure마다 `data-rc-ready="1"`이 붙었다.
- **도식:** 원문의 `pre.mermaid`마다 SVG가 그려졌다.
- **네트워크:** 대기 중인 요청이 없다.

외부 요청(CDN 글꼴·라이브러리)이 실패하거나 15초 안에 조건이 갖춰지지 않으면, 그 문서는 판정하지 않는다. 대신 환경 실패로 기록하고 종료 코드 2를 돌려준다. 원문에 `RC.demo` 호출이 있는데 `data-rc-ready`가 오지 않으면, 환경 실패가 아니라 애니메이션 항목의 '측정 불가'로 기록하고 실패로 센다. 엔진이 깨져 정적 목록으로 물러난 문서가 통과하지 않게 하기 위해서다.

`--mode auto|step`은 주소에 `?rc-mode=` 인자를 붙인다. 테마는 `prefers-color-scheme`을 밝음과 어두움으로 각각 흉내 낸 채 문서를 새로 열어 잰다. Mermaid 색이 문서를 열 때 한 번 정해지기 때문이다.

## 기계 판정

`eval/gates.py`는 항목마다 통과·실패와 측정값을 기록하고, 실패가 하나라도 있으면 종료 코드 1을 돌려준다. 명령 형식은 `python eval/gates.py <html>… [--mode auto|step] [--only motion|layout|content] [--base-checks <폴더>] [--out <결과.json>]`이다.

문턱값과 용어 정의는 상위 설계의 표를 따른다. 측정 방법은 아래와 같다.

| 항목 | 대상 | 측정 방법 |
|---|---|---|
| `dwell` | motion | 아래 「체류 시간 측정」 |
| `step-anim` | motion | 단계 넘김에서 '다음'을 누른 뒤 타임라인 시간이 멈출 때까지의 길이(허용 오차 0.1초)와, 누르지 않고 3초 동안 단계가 바뀌지 않는지를 잰다 |
| `step1` | motion | 처음 연 상태의 타임라인 시간이 0.05초 이하이고, 재생(자동) 또는 다음(넘김)을 누른 뒤 첫 단계 끝 라벨 `e0`에 도달할 때까지 0.2초 이상 걸리는지 잰다 |
| `note-near` | motion | 아래 「설명 상자 판정」 |
| `active-visible` | motion | 아래 「설명 상자 판정」 |
| `svg-font-390` | motion | 390×844 창에서 SVG 안의 모든 글자(SVG `text`와 `foreignObject` 안의 HTML 글자)의 화면상 크기가 11px 이상인지 잰다 |
| `figure-overflow-390` | motion | 390 폭에서 figure가 문서 가로 넘침을 만들지 않는지 잰다. figure가 자기 스크롤 상자 안에서 넘치는 것은 허용한다 |
| `contrast-text` | layout | 아래 「대비 판정」 |
| `contrast-graphic` | layout | 아래 「대비 판정」 |
| `cvd` | layout | 계열 색 토큰을 제2색각 행렬(Machado 2009)로 변환한 뒤, 쌍마다 CIE76 색차가 15 이상인지 두 테마에서 잰다 |
| `html-font-390` | layout | 390 폭에서 SVG 밖 HTML 글자의 화면상 크기가 11px 이상인지 잰다 |
| `overflow-390` | layout | 390 폭에서 문서 스크롤 폭이 창 폭을 넘지 않는지 잰다 |
| `table-col-390` | layout | 390 폭에서 표 셀의 화면상 폭이 56px 이상인지 잰다. 스크롤 상자 안의 표도 잰다 |
| `page-number` | layout | 페이지형 문서의 페이지마다, figure와 표 밖에서 'n / m'(m은 그 문서의 페이지 수) 모양으로 보이는 글이 하나인지 잰다 |
| `hash-nav` | layout | 주소 끝 `#p2`로 처음 열 때와, 1페이지에서 주소 끝을 `#p2`로 바꿀 때 2페이지가 보이는지 잰다 |
| `rules-motion` | motion | `checks/anim.py`의 `RULES` 위반이 0건인지 잰다 |
| `rules-layout` | layout | `checks/style.py`의 `RULES` 위반이 0건인지 잰다 |
| `rules-all` | content | `check.py`의 모든 규칙(금지어 검사 포함) 위반이 0건인지 잰다 |

화면상 크기는 조상 변환을 모두 반영한 값이다. 글자 요소의 계산된 글자 크기에 화면 변환 행렬(`getScreenCTM` 또는 경계 상자 대비 비율)의 배율을 곱해 얻는다.

`--only`가 없으면 모든 항목을 잰다. `--mode auto`에서는 `step-anim`을, `--mode step`에서는 `dwell`을 재지 않는다. `--mode`가 없으면 figure의 `data-rc-mode`를 읽어 그 방식의 항목을 재고, 이 속성이 없으면 `auto`로 본다. 컴포넌트별 판정에 쓰는 묶음은 상위 설계 「완료 기준」 표를 따른다. C1은 `--only motion`, C2는 `--only layout`, C3는 `--only content`, 최종 통합은 `--only` 없이 쓴다.

`--base-checks <폴더>`를 주면, 규칙 항목을 후보 워크트리의 `checks/`와 그 폴더(기준 커밋의 `checks/` 사본)로 각각 실행한다. 둘 다 위반이 0건이어야 통과다. 피평가 컴포넌트가 자기 규칙 모듈을 느슨하게 고쳐 통과하는 일을 막기 위해서다. L1의 공식 측정은 이 인자를 쓴다.

해당 없음은 원문으로만 판정한다. 원문에 `RC.demo` 호출이 없으면 애니메이션 항목(`dwell`·`step-anim`·`step1`·`note-near`·`active-visible`)이 해당 없음이다. 원문에 SVG가 없으면 `svg-font-390`과 `figure-overflow-390`이 해당 없음이고, 페이지형이 아니면 `page-number`와 `hash-nav`가 해당 없음이다. 해당 없음은 통과로 센다. `data-rc-active`가 없는 엔진에서는 `note-near`와 `active-visible`을 측정 불가로 기록하고 실패로 센다.

`hash-nav`의 페이지 전환 코드는 관리 블록 밖의 문서 코드다. 그래서 고정 견본으로는 C2의 템플릿 변경을 잴 수 없다. L1은 C2를 판정할 때 이 항목을 `template-paged.html`에서 재고, 최종 통합에서는 재생성본에서 잰다. 고정 견본의 `hash-nav` 결과는 기록만 하고 판정에 쓰지 않는다.

출력 JSON은 문서마다 `{file, mode, theme, env, items: [{id, target, status, value, detail}]}` 형태다. `status`는 `pass`, `fail`, `unmeasurable`, `n/a` 가운데 하나이고, `env`는 `ok` 또는 `env-fail`이다.

## 체류 시간 측정

`dwell`은 벽시계 대신 타임라인을 직접 옮겨 가며 측정한다. 병렬 실행의 부하로 프레임이 늦어도 값이 흔들리지 않게 하기 위해서다. 상위 설계의 계약에 따라 자동 재생의 머무는 시간은 `fig._rcTl` 안에 있고, 단계 i는 라벨 `e(i-1)`(첫 단계는 0)에서 `e(i)`까지다.

측정 순서는 다음과 같다.

1. figure가 있는 페이지로 이동하고, '처음부터'를 누른다.
2. 타임라인을 0부터 끝까지 0.05초 간격으로 옮기며, 시점마다 figure 안의 보이는 글을 기록한다.
3. 단계마다 글이 마지막으로 바뀐 시점(글 완료 시점)을 찾는다. 체류 시간은 `e(i)`에서 글 완료 시점을 뺀 값이다.
4. 단계마다 n을 구하고, 체류 시간을 1초 + n÷8초 이상, 그 값 + 3초 이하와 비교한다.

보이는 글은 figure 안에서 계산된 불투명도(조상 포함)가 0.05보다 크고 `display`가 `none`이 아닌 글 요소의 글이다. 조작 줄(`.demo-ctl`)과 단계 목록(`.demo-steps`)은 뺀다. 창 밖이나 스크롤 상자 밖의 글도 보이는 글에 든다.

n은 요소 단위로 센다. `e(i)` 시점의 보이는 글 요소 가운데, `e(i-1)` 시점에 같은 요소가 같은 글로 보이지 않던 요소를 고른다. 그 요소들의 글자 수 합계가 n이며, 공백은 빼고 숫자 묶음도 숫자 하나를 1자로 센다. 글이 바뀐 요소는 새 글 전체를 센다.

## 설명 상자 판정

`note-near`와 `active-visible`은 단계 끝(`e(i)`)마다 현재 노드(`[data-rc-active]`)와 보이는 설명 상자(`.rc-note`)의 위치로 판정한다.

- **거리:** 두 요소의 화면상 경계 상자 사이 거리가 48px 이하다.
- **겹침:** 설명 상자 경계 상자가 무대 요소와 겹치지 않는다. 노드 도형·글자·간선 이름표는 경계 상자로 판정한다. 간선은 경로 위를 2px 간격으로 찍은 점이 설명 상자 안에 드는지로 판정한다. 설명 상자 자신과 그 안의 요소, 스틱맨 아이콘은 무대 요소에서 뺀다.
- **화면 안:** 측정기는 재생 전에 figure 윗변을 창 윗변에 맞춰 한 번만 스크롤하고, 그 뒤로는 스크롤하지 않는다. 단계 끝마다 두 요소가 1280×800 창 안에 모두 들어오는지 본다. 그 뒤의 스크롤은 엔진의 몫이다.

## 대비 판정

글자 대비와 그래픽 대비는 렌더된 색으로 재고, 바탕을 정할 수 없는 글자는 측정 불가로 기록한다.

- **SVG 밖 HTML 글자:** 글자색과, 조상으로 올라가며 처음 만나는 불투명 바탕색의 대비를 잰다.
- **SVG 안 글자:** 글자 중심점에서 그 글자 아래에 그려진 도형의 채움색을 바탕으로 쓴다. 도형이 없으면 SVG 밖 바탕 규칙을 쓴다.
- **측정 불가:** 반투명 바탕이나 배경 이미지처럼 바탕을 정할 수 없으면 측정 불가로 기록하고 실패로 세지 않는다. 측정 불가 개수는 결과에 남긴다.
- **기준:** 글자는 4.5:1이다. 24px 이상이거나, 굵은 18.66px 이상인 큰 글자는 3:1이다(WCAG 1.4.3). 상위 설계의 '본문 글자 4.5:1'에 큰 글자 예외를 붙인 값이며, 리포트에 상위 설계와 다른 점으로 적는다.
- **그래픽:** 막대(`.fill`), 차트 계열 선과 막대(ECharts는 SVG로 그린다), 도식 노드 테두리의 렌더된 색이 인접 바탕과 3:1 이상인지 잰다(WCAG 1.4.11).

## 스크린샷

`eval/shoot.py`는 검토 서브에이전트에게 줄 장면과 글을 만든다. 명령 형식은 `python eval/shoot.py <html> <출력 폴더> [--mode auto|step]`이다.

페이지형 문서는 페이지마다, 단일 문서는 화면 높이 단위로 1280×800과 390×844 장면을 찍는다. 애니메이션은 figure마다 단계 끝 장면을 1280 폭에서 찍는다. 파일 이름은 `<페이지>-<폭>.png`와 `<figure id>-s<단계 번호>.png`다. 같은 폴더에 페이지별 보이는 글을 `<페이지>.txt`로 남기고, 장면 목록을 `index.json`으로 남긴다. 이해도 시험의 검토자는 이 폴더만 받는다.

## 체크리스트와 프롬프트

`eval/checklist.md`는 화면을 보고 판정할 수 있는 예/아니오 항목만 두고, 항목마다 범주·적용 대상·대응 결함을 붙인다. 범주는 사용자 만족도, 심미성, 구성, 이해 용이성, 논리 전개다. 적용 대상은 그 항목을 고칠 수 있는 컴포넌트로 정한다. 애니메이션·도식·차트 표현은 `motion`, 색·배치·페이지 틀은 `layout`, 문장·절 구성·근거·결정 요청은 `content`다.

항목은 시각 검토 기준선(`docs/superpowers/research/2026-10-04-report-quality/visual-review-baseline.md`)의 결함마다 하나 이상 대응해야 한다. 대응 결함을 고른 기준은 다음 결함들이다.

- 애니메이션 단계가 읽기 전에 넘어간다.
- 설명이 도형에서 떨어져 하단 자막으로만 나온다.
- 강조 노드와 설명을 한 화면에서 함께 볼 수 없다.
- 현재 노드와 지나온 노드가 구분되지 않는다.
- 390 폭에서 표를 읽기 어렵거나 가로 스크롤 단서가 없다.
- 페이지 번호가 두 번 보인다.
- 용어 풀이 배치가 깨진다.
- 제목만 읽으면 논지가 보이지 않는다.
- 같은 사실을 불릿·도식·표로 반복한다.
- 결정 요청에 권장안이 없다.
- 전후 비교의 기준선이 끝 장면에서 사라진다.
- 불릿과 표의 내용이 서로 다르다.
- 근거 없는 주장이 있다.

체크리스트 검토는 항목마다 `{id, answer: "예"|"아니오"|"해당 없음", evidence}`를 돌려준다. 3회 결과는 항목마다 다수결로 묶는다. 셋이 모두 다르면 '해당 없음'이 끼어 있는 경우이므로 '아니오'로 본다. 적용 대상별 충족률은 다수결이 '예'인 항목 수를, 다수결이 '해당 없음'이 아닌 항목 수로 나눈 값이다. `eval/baseline/`에는 견본별·항목별 3회 결과와 다수결을 JSON으로 남겨, L1이 하락 판정에 그대로 쓰게 한다.

`eval/prompts/`의 틀에는 검토자가 받는 입력(shoot.py 출력 폴더), 판정 규칙, 출력 JSON 형식을 적는다. 이해도 시험·심어 둔 오류·제목 연결 틀에는 질문이나 오류를 넣을 자리만 두고, 실제 질문과 정답은 넣지 않는다. 이해도 시험 틀의 출력에는 질문별 답, 추가로 필요한 질문 목록, 찾은 오류를 담는다. 검토자는 작업 내용과 저장소를 모른다고 가정하고 쓴다.

## 기준선과 검증

C0은 기준 커밋 `512d308`의 엔진·CSS로 고정 견본을 다시 빌드해 기준선을 재고, 측정 도구가 결함을 잡는지와 문턱값을 지킬 수 있는지를 함께 확인한다. 기준선 기계 판정은 `--mode auto`와 `--mode step`, 밝은 테마와 어두운 테마를 모두 재서 `eval/baseline/`에 기준 커밋 해시와 함께 남긴다.

결함 검출 기준은 기준선에서 다음 항목이 실패로 나오는 것이다.

| 고정 견본 | 항목 | 기준선 결함 |
|---|---|---|
| 04-rules | `dwell` | 단계당 약 0.32초 |
| 04-rules | `step1` | 1단계 생략 |
| 04-rules | `note-near` | 측정 불가(설명 상자와 현재 노드 표시 없음) |
| 04-rules | `svg-font-390` | 노드 이름표 화면상 약 9.4px |
| sample-anim | `svg-font-390` | 설명 상자 글 화면상 약 5~10px |
| sample-anim | `contrast-graphic` | 막대 대비 2.58:1 |
| session-report | `page-number` | 페이지 번호 두 번 표시 |

session-report의 표 결함은 기계 판정으로 잡히지 않는다. 표가 모두 가로 스크롤 상자 안에 있고, 셀 폭(실측 75px 이상)도 문턱값을 넘기 때문이다. 이 결함은 체크리스트 항목으로 판정한다.

실현 가능성은 엔진을 고치지 않고 지킬 수 있는 항목으로만 확인한다. `eval/validation/minimal-anim.html`은 직접 그린 SVG 무대에 현재 엔진의 `RC.note`·`RC.icon`·`RC.fx`를 써서 만든다. 이 견본이 `dwell`(1단계 제외), `note-near`, `active-visible`, `svg-font-390`, `figure-overflow-390`을 통과해야 한다. 현재 엔진이 `data-rc-active`를 달지 않으므로 이 견본에서는 문서 쪽 코드가 연출 중인 도형에 이 속성을 단다. 머무는 시간은 단계 안에 `tl.to` 빈 트윈을 넣어 맞춘다. `step1`과 `step-anim`은 C1이 고칠 엔진 동작이라 이 확인에서 뺀다.

체크리스트 판별력은 기준선 고정 견본과 `minimal-anim.html`에 체크리스트 검토를 3회씩 실행해 확인한다.

- **흔들림:** 세 결과가 모두 같지 않은 항목을 흔들리는 항목으로 표시한다.
- **음성 대조:** 대응 결함이 있는 견본에서 다수결이 '예'로 나온 항목을 판별 실패로 표시한다.
- **양성 대조:** `minimal-anim.html`에서 지킨 조건에 대응하는 `motion` 항목의 다수결이 '아니오'면 판별 실패로 표시한다.
- **보정:** 표시된 항목은 문구를 고쳐 다시 잰다. 다시 재기는 두 번까지다. 그래도 표시가 남은 항목은 체크리스트에서 빼고 `eval/baseline/checklist-agreement.md`에 이유와 함께 적는다.

`eval/rebuild.py`는 `python eval/rebuild.py <출력 폴더>` 형식으로 쓴다. `bench/fixed/`의 견본을 출력 폴더에 복사한 뒤 build.py로 빌드하고, `bench/`는 바꾸지 않는다. build.py가 실패하면 그 종료 코드를 그대로 돌려준다. 빌드 뒤에는 각 사본의 관리 블록이 현재 워크트리의 `report-base.css`·`report-demo.css`·`report-charts.js`와 같은지 대조하고, 다르면 실패한다.

단위 시험(`python -B -m unittest discover -s tests`)은 다음을 확인한다. 각 시험은 합성 HTML이나 수치로 입력과 기대 결과를 정한다.

- **측정 함수:** 체류 시간과 n 계산, 화면상 글자 크기(SVG `text`와 `foreignObject` 포함), 대비, 색각 변환과 색차, 스크롤 상자 판정, 간선 점 겹침 판정, 'n / m' 판정
- **실패 경로:** `data-rc-active`는 있는데 설명 상자가 없거나 60px 떨어진 합성 견본에서 `note-near`가 실패한다. 현재 노드가 창 밖인 견본에서 `active-visible`이 실패한다.
- **해당 없음과 측정 불가:** `RC.demo` 호출이 있는데 엔진이 정적 목록으로 물러난 견본은 측정 불가 실패다. 호출이 없는 견본은 해당 없음이다.
- **명령:** rebuild.py가 build.py 실패 코드를 전달하고 `bench/`를 바꾸지 않는다. shoot.py가 정해진 이름의 파일과 `index.json`을 만든다. 프롬프트 틀에 질문 자리 표시만 있고 정답 문구가 없다.

체크리스트 검토 3회는 C0이 자기 산출물을 검증하는 실행이며, 상위 설계가 L2에게 금지한 공식 측정이 아니다.

## 함정

이번 세션에서 확인한 엔진 동작은 다음과 같고, 측정 도구가 이 동작을 그대로 반영해야 한다.

- **자기 판정 배제:** `RC.check`는 겹침과 글 규칙만 본다. gates.py는 `RC.check`를 판정에 쓰지 않는다.
- **1단계 생략의 동작:** 처음 열면 엔진이 타임라인을 `e0`(1단계 끝)으로 옮겨 둔다. 재생을 누르면 거기서부터 진행하고, 다음을 누르면 2단계로 간다(`report-charts.js` 404~430행).
- **단계 표시의 위치:** 페이지형 문서에는 페이지 넘김 막대에도 `.cnt`가 있고, 애니메이션의 `.cnt`보다 앞에 있다. gates.py는 `.cnt`를 쓰지 않고 `fig._rcTl` 라벨을 쓴다.
- **숨은 페이지:** 보이지 않는 페이지의 그림은 폭이 0이다. 애니메이션을 재기 전에 그 페이지로 이동한다.
- **foreignObject 글자:** Mermaid 노드 이름표와 설명 상자 글은 SVG 안 `foreignObject`의 HTML이다. 04-rules의 흐름도에는 SVG `text`가 없다.

## 산출 계약

C0의 L2는 브랜치까지만 만들고 병합·push하지 않는다. 리포트는 저장소 밖 스크래치 경로에 쓰고 브랜치에 커밋하지 않는다. 리포트에는 다음을 적는다.

- 변경 파일과 시험 결과
- 기준선 결과 요약과 결함 검출 표의 항목별 결과
- 실현 가능성과 체크리스트 판별력 결과(뺀 항목과 이유 포함)
- 상위 설계와 다르게 정한 점
- 브랜치 이름

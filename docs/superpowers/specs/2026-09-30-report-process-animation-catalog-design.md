# 보고서 작성 과정과 애니메이션 목록 설계

작성일 2026-09-30 · 대상 스킬 `writing-html-reports`

## 목적과 범위

이 설계는 보고서 작성을 0~6단계의 정해진 과정으로 만들고, 애니메이션 선택을 닫힌 목록과 등록 절차로 관리한다. 같은 요구사항으로 두 번 실행해도 같은 단계와 같은 애니메이션 유형이 선택되게 하는 것이 목표다. 각 단계의 결과는 check.py 또는 `RC.check`로 확인할 수 있어야 한다.

지금 스킬은 동작 예시를 구조(처리 과정) 한 유형으로만 정의한다. 구조 외의 애니메이션은 실행할 때마다 모델이 새로 떠올려야 하므로 결과가 실행마다 달라진다. 제안서v2.1 폴더 아홉 문서를 검토한 결과 구조 외의 후보가 여섯 유형 나왔다(전후 전환, 선별, 표본 누적, 규칙 적용 재생, 충격 적용, 분해 합산).

사용자가 정한 조건은 다음과 같다.

- **과정 정의 우선:** 견본보다 과정과 목록의 틀을 먼저 확정한다.
- **애니메이션 개수:** 별 표시 페이지당 1개, 파일당 최대 3개다.
- **점수 되먹임 차단:** 작업 순서는 4 시각화 → 5 핵심 페이지 → 6 애니메이션을 유지하고, 동작 예시 도식의 마름모는 핵심 페이지 점수에서 뺀다.
- **목록 상태:** 일곱 유형을 모두 등록하고, 견본이 있는 유형만 사용한다.
- **인물 그림 출처:** '졸라맨'을 '스틱맨'으로 부르고, 직접 그리지 않고 라이선스 위험이 없는 외부 그림(Open Peeps)을 쓴다.
- **인물 그림 모양:** 얼굴이 보이는 상반신을 지금보다 2배 크게(80) 두고, 분기·완료·실패에서 주의를 환기한다.
- **인물 그림 포함 범위:** 인물 그림 데이터는 시각화가 있는 모든 문서에 넣는다.

기존 규격(흰 바탕, 1px 선, 토큰 색, 글자 수 30자, 글 등장 1초, 쌍 배치, 겹침 금지)은 모든 유형에 그대로 적용한다. 사용자가 명시한 요구사항이 모든 규칙보다 우선한다는 원칙도 유지한다.

## 작업 과정

보고서 작성은 0~6단계를 차례로 거치며, 0·1·2단계와 새 애니메이션 유형 등록에서 사용자 승인을 받는다. 앞 단계의 산출물이 뒤 단계의 입력이므로 순서를 바꾸지 않는다.

| 단계 | 산출물 | 확인 방법 | 사용자 승인 |
|---|---|---|---|
| 0. 독자와 전달 방식 | 독자, 전달 방식(발표·사전 배포·인쇄·오프라인) | 대화에서 사용자 확인 | 필요 |
| 1. 묶음 분할 | 파일 목록과 파일마다 답하는 독자의 질문 하나 | 문서 간 기간·수치·용어 일치 대조 | 필요 |
| 2. 파일 내용 정리 | 요약 결론, 결론별 근거 페이지(`data-src`), 핵심 수치 출처 | check.py가 `data-src` 누락을 검출 | 필요(요약 결론) |
| 3. 페이지 내용 정리 | 결론·근거·중요 포인트·유의사항·출처 순서의 페이지 | check.py가 근거 없는 페이지를 검출 | 불필요 |
| 4. 시각화 | 시각화 기준표에 따른 차트·도식 | 시각화 점검 | 불필요 |
| 5. 핵심 페이지 | ★·☆ 표시 | check.py 점수표 | 불필요 |
| 6. 애니메이션 | 별 표시 페이지마다 1개 또는 없음 | `RC.check` 통과, 선택 이유 보고 | 새 유형 등록 때만 필요 |

0단계의 결과는 뒤 단계를 다음과 같이 바꾼다.

- **인쇄 전달:** 6단계를 생략한다. 정지 도식이나 표가 결론을 보여 준다.
- **오프라인 열람:** 4·6단계에서 CDN 도구(ECharts, Mermaid, GSAP)를 쓰지 않고 정지 SVG와 표만 쓴다.
- **발표:** 발표자가 '다음' 버튼으로 한 단계씩 넘기는 기존 방식을 쓴다.

기존 HTML을 고치는 작업은 본문 불변 원칙을 유지한다. 5단계 결과는 참고로만 알리고, 4·6단계는 후보 목록만 보고한다.

1단계의 분할 기준은 '파일 하나가 독자의 질문 하나에 답한다'이다. 여러 파일에 같은 수치가 나오면 원천 자료 하나에서 가져오고, 기존 완료 기준의 '문서 간 일치' 대조를 이 단계에서 먼저 실행한다.

## 애니메이션 목록

애니메이션은 아래 일곱 유형으로 정의하며, 유형마다 같은 칸을 채운다. 칸은 구조 동작 예시를 기준 틀로 삼아 정했다.

| 유형 | 보여 주는 것 | 내용 신호 | 마지막 프레임 | 쓰지 않는 조건 | 상태 |
|---|---|---|---|---|---|
| 구조 | 예시 1건이 처리 과정과 분기를 지나는 순서 | 흐름도, 판단 분기가 있는 과정 | 마지막 도형의 처리 결과 | 3단계 미만 | 사용 가능 |
| 전후 전환 | 같은 항목의 값이 기준선에서 제안안으로 바뀌는 변화 | 결론이 'A에서 B로'의 비교 | 제안안의 값과 변화량 | 항목 2개 미만 | 사용 가능 |
| 규칙 적용 재생 | 규칙이 시간 순서대로 발동해 경로를 바꾸는 과정 | '~하면 ~한다' 규칙과 시계열 | 규칙 적용 전후의 누적값 차이 | 발동 시점이 없음 | 사용 가능 |
| 선별 | 후보 N개가 기준을 거쳐 소수만 남는 과정 | 후보 수와 통과 수 | 남은 개수 | 후보 5개 미만(표로 둔다) | 견본 대기 |
| 표본 누적 | 시행이 쌓이며 확률이 드러나는 과정 | 확률, 검정력, 모의실험 N회 | 해당 결과의 비율 | 시행별 결과가 없음 | 견본 대기 |
| 충격 적용 | 시나리오를 보유에 적용한 손익 | 스트레스, 금리 충격 | 시나리오별 손익 범위 | 시나리오 2개 미만 | 견본 대기 |
| 분해 합산 | 원천별 값이 쌓여 총계가 되는 과정 | 원천별 값의 합으로 이루어진 총계 | 총계와 비교 대상의 차이 | 원천 2개 미만 | 견본 대기 |

'사용 가능'은 `tests/sample-viz.html`에 견본이 있고 그 견본이 `RC.check`를 통과한 상태다. '견본 대기'는 목록에 등록만 되어 있고 견본이 없는 상태다. 전후 전환과 규칙 적용 재생의 견본은 이 설계의 구현에서 만든다.

모든 유형에 공통으로 적용하는 규칙은 다음과 같다.

- **예시 데이터:** 설명 상자에 보여 줄 값을 문서의 자료에서 먼저 발췌한다.
- **글 규칙:** 설명 상자 30자 이하, 글 등장 1초 이내, 표시 시간 min(1 + 글자 수 ÷ 10, 4)초를 유지한다.
- **복잡도 신호:** 단계 설명이 30자 안에 들어가지 않으면 구조를 더 잘게 나누거나 구체화한다.
- **용어 풀이:** 설명 상자에 넣지 않고 figure의 출처 줄 아래 `.note`에 둔다.
- **정지 상태:** 인쇄하거나 재생하지 않는 독자도 결론을 읽을 수 있도록, 마지막 프레임 또는 함께 둔 표가 페이지 결론의 수치를 보여 준다.

## 선택 규칙과 등록 절차

6단계는 별 표시 페이지마다 아래 순서로 애니메이션 하나를 고르고, 목록 밖 유형은 등록 절차를 거친 뒤에만 쓴다. 선택 기준을 '마지막 프레임이 결론의 수치를 보여 주는가'로 둔 이유는 `TITLE-PROOF`(본문이 제목을 증명한다)를 애니메이션에 적용하기 위해서다.

1. 페이지 내용이 목록의 내용 신호에 해당하는 유형을 후보로 모은다. 후보가 없으면 애니메이션을 만들지 않는다.
2. 마지막 프레임이 페이지 결론(`ul.pts` 첫 줄)의 수치를 보여 주는 후보만 남긴다.
3. 여럿이 남으면 결론의 수치를 더 많이 보여 주는 후보를 고르고, 그래도 같으면 목록 순서를 따른다.
4. 고른 유형이 '견본 대기'이면 적용하지 않고 보고에서 제안한다. 사용자가 승인하면 견본을 먼저 만들어 '사용 가능'으로 바꾼 뒤 적용한다.

목록에 없는 유형이 필요하면 표의 칸을 모두 채워 사용자에게 제안한다. 승인을 받으면 견본을 만들고 `RC.check`를 통과시킨 뒤, SKILL.md 표와 check.py 목록에 함께 추가한다.

애니메이션 figure에는 `data-anim="유형 이름"`을 적는다. 이 속성이 선택한 유형을 기록하고, check.py가 목록과 대조하는 근거가 된다.

## 인물 그림

동작 예시의 인물 그림은 Open Peeps의 조각을 조합한 한 인물이며, 상황별로 자세와 표정을 바꾼다. Open Peeps(Pablo Stanley)는 CC0 1.0으로 공개되어 수정과 재배포에 제약이 없다.

| 아이콘 이름 | 상황 | 자세 | 표정 |
|---|---|---|---|
| `person` | 분기(고민) | 팔짱(crossed_arms-1) | Suspicious |
| `person-guide` | 안내 | 손가락으로 가리킴(pointing_finger-1) | Explaining |
| `person-done` | 완료 | 손바닥을 내밂(robot_dance-1) | Smile Big |
| `person-fail` | 실패 | 손을 내리고 섬(resting-2) | Tired |

머리는 모든 그림에서 Short 2로 같게 둔다. 원본 묶음에는 두 팔을 드는 환호 자세가 없으므로, 완료는 표정과 손 동작으로 전달한다. 코드와 문서의 '졸라맨'은 '스틱맨'으로 바꾼다.

인물 그림은 상반신(머리~허리)을 80×80에 둔다. 기존 졸라맨 높이 40의 2배다. 전신을 80에 두면 얼굴 높이가 13 정도라 표정이 읽히지 않아 상반신을 택했다. 분기 그림에는 기존 이름 `person`을 그대로 쓰므로, 기존 `RC.fx.think` 호출은 바꾸지 않아도 된다.

상황마다 쓰는 때와 효과는 아래와 같고, 효과는 모두 기존 `RC.fx` 함수로 연출한다.

| 아이콘 이름 | 쓰는 때 | 효과 |
|---|---|---|
| `person-guide` | 시나리오 첫 단계에서 예시 데이터를 소개할 때 | 등장(`pop`) |
| `person` | 판단 도형의 단계 | 갸웃과 물음표 깜빡임(`think`) |
| `person-done` | 판정이 통과이거나 마지막 도형이 정상 완료인 단계 | 표정 교체(`swap`)와 등장(`pop`) |
| `person-fail` | 판정이 거부·실패인 단계 | 표정 교체(`swap`)와 흔들림(`shake`) |

`tools/build-peeps.py`는 로컬 원본(`assets/open-peeps-src/Flat Assets.zip`)에서 네 그림을 만들어 `report-peeps.js`로 쓴다. 처리 순서는 다음과 같다.

1. 자세·머리·얼굴 조각을 원본의 조합 좌표(자세 `translate(-121,634)`, 머리 `translate(404,180)`, 얼굴은 머리 안 `translate(159,186)`)로 합친다.
2. 발밑 그림자 경로를 지운다.
3. 검은 채움은 선 색 토큰(`ink`)으로 바꾸고 흰 채움은 바탕 토큰(`paper`)으로 바꾼다. 다른 채움 색이 나오면 멈추고 알린다.
4. viewBox를 머리 위부터 허리까지로 잘라 상반신만 보이게 한다. 자른 범위는 스크립트 상수로 두고, 네 그림에 같은 범위를 쓴다.
5. 좌표를 반올림한다.

build.py는 `report-peeps.js`를 연결 코드 블록에 함께 넣는다. 인물 그림을 쓰지 않는 문서에도 넣으므로, 시각화가 있는 문서는 약 95KB 커진다. 오프라인 문서는 0단계 규칙에 따라 6단계를 생략하고 연결 코드 블록도 두지 않으므로, 인물 그림이 필요하지 않다.

원본 묶음 네 개(약 55MB)는 `.gitignore`로 저장소에서 제외하고 이 PC에만 둔다. 저장소에는 가공한 `report-peeps.js`와 `assets/LICENSE-open-peeps.md`만 둔다. `assets/LICENSE-open-peeps.md`에는 출처, CC0 1.0 표기, 조합 목록, 다시 받는 주소(`https://gum.co/openpeeps`), 원본 파일 이름과 SHA-256을 적는다. 이 PC의 원본이 사라져도 같은 파일을 다시 받아 체크섬으로 확인한 뒤 `report-peeps.js`를 다시 만들 수 있다.

## 검사기 변경

check.py는 애니메이션 목록을 원본으로 보유하고, 네 가지 위반을 새로 검출한다. 핵심 페이지 점수의 분기 수 B는 `data-anim`이 있는 figure 안의 마름모를 세지 않는다.

- **유형 누락:** `RC.demo`로 만드는 figure에 `data-anim`이 없다.
- **허용 밖 유형:** `data-anim`이 목록 밖 유형이거나 '견본 대기' 유형이다.
- **페이지당 초과:** 한 페이지(`section.page`)에 애니메이션이 2개 이상이다.
- **별 없는 페이지:** 별 표시(`core`·`key`)가 없는 페이지에 애니메이션이 있다.

B를 셀 때는 페이지 본문에서 `data-anim`이 있는 `<figure>…</figure>` 구간을 먼저 잘라 낸 뒤 `<polygon>`과 Mermaid `{…}` 노드를 센다. 같은 페이지에 동작 예시와 정지 도식이 함께 있으면 정지 도식의 마름모만 세어야 하며, 이 사례를 단위 시험으로 둔다.

기존 파일당 3개 상한은 그대로 둔다. 새 위반 네 가지는 새 함수 `anim_violations(html)`에서 검출한다. 원본 HTML을 함께 준 수정 작업에서는 기존 `script_violations`와 같은 방식을 따른다. 원본에서도 같은 문구로 검출된 위반은 '참고'로 출력하고 위반 수에서 뺀다. `main()`은 `anim_violations(new)`와 `anim_violations(old)`를 비교해 이 구분을 적용한다.

목록은 SKILL.md 표와 check.py 두 곳에 두고, 두 목록의 유형 이름과 상태가 같은지 확인하는 시험을 둔다. 한쪽에서 다른 쪽을 생성하는 방식도 검토했다. 그러나 SKILL.md 안에 생성 구간과 생성 도구를 새로 두어야 해서, 일곱 줄짜리 표에는 시험 하나가 더 단순하다고 판단했다.

## 견본과 문서

## 가정과 위험

인물 그림 데이터 약 95KB는 조합 SVG 네 개를 소수 첫째 자리로 반올림해 측정한 값이며, 구현 뒤 실제 크기를 다시 측정해 보고한다. 원본 그림의 채움 색은 검은색과 흰색 두 가지라고 가정했고, 다른 색이 나오면 `tools/build-peeps.py`가 멈추고 알린다.

파일당 3개, 페이지당 1개 상한은 check.py가 위반으로 검출한다. 사용자가 상한을 넘기라고 명시하면 요구사항을 따르고, 보고에 '따르지 않은 규칙'으로 적는다.

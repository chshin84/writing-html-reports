# C2 페이지 틀·CSS 설계

작성일 2026-10-04. 상위 설계는 `docs/superpowers/specs/2026-10-04-report-quality-architecture-design.md`이고, 측정 도구(C0 하네스) 설계는 `docs/superpowers/specs/2026-10-04-c0-eval-harness-design.md`다.

## 목적과 범위

C2는 공통 CSS와 템플릿을 고쳐 색 대비, 모바일 배치, 페이지 틀의 결함을 없애고, 새 제목 체계와 C3용 화면 요소의 틀을 만든다. 상위 설계와 이 문서가 다르면 상위 설계를 따르고, 다르게 정한 점은 리포트에 적는다.

이 문서가 쓰는 이름은 다음과 같다.

- **L1:** 메인 세션이다. 공식 측정과 병합을 맡는다.
- **L2:** C2를 맡는 서브오케스트레이터다. 이 문서의 독자이고, 사용자와 대화하지 못한다.
- **BLOCKED:** L2가 L1이나 사용자의 결정이 필요할 때 작업을 멈추고 질문과 함께 돌려주는 상태다.
- **C0 하네스:** 다른 컴포넌트를 판정하는 측정 도구다(`eval/gates.py`, `eval/shoot.py`, `eval/checklist.md`).
- **고정 견본:** 호출 코드까지 고정한 HTML 사본이다(`bench/fixed/`). `eval/rebuild.py`가 현재 워크트리의 CSS·JS를 관리 블록에 넣어 다시 빌드한다.
- **관리 블록:** `build.py`가 `report-base.css`·`report-demo.css`·`report-charts.js`의 사본으로 채우는 문서 안 구간이다. 관리 블록 밖의 문서 스크립트(페이지 전환 등)는 다시 빌드해도 바뀌지 않는다.
- **C1·C3:** 애니메이션 엔진과 보고서 내용 규격 컴포넌트다. C1은 `report-demo.css`와 `.demo-*`를, C3는 `SKILL.md`와 `checks/content.py`를 소유한다.

소유 파일은 다음과 같다. 그 밖의 파일은 읽기만 하고, 고쳐야 하면 BLOCKED로 돌려준다.

- **스타일과 템플릿:** `report-base.css`, `template.html`, `template-paged.html`
- **규칙과 문서:** `checks/style.py`, `보고서-규격.md`, `tests/test_style.py`
- **작업 기록:** `docs/superpowers/plans/2026-10-04-c2-page-frame.md`와 그 리뷰 기록

개선은 되도록 CSS로 한다. CSS는 관리 블록에 들어가 고정 견본과 다른 세션의 기존 문서에도 반영되지만, 템플릿 스크립트는 새로 만드는 문서에만 들어가기 때문이다.

## 색

색 토큰은 대비와 색각 구분 기준을 지키되, 기존 문서의 인상이 바뀌지 않도록 색상 계열을 유지하고 명도·채도만 조정한다. 토큰은 밝은 테마(`:root`), `prefers-color-scheme: dark`, `[data-theme="dark"]` 세 곳에 정의되어 있으므로 세 곳을 함께 고친다. 기존 토큰 이름은 지우지 않는다.

- **보조 강조색:** `--accent-2`는 막대 채움(`.fill`), ECharts 다섯째 계열, 애니메이션에서 지나온 도형의 테두리에 쓰인다. 이 토큰을 두 테마에서 `--paper`와 `--tint` 바탕 대비 3:1 이상으로 바꾼다. 동시에 `--accent`와 구분되도록, 두 토큰의 대비를 1.5:1 이상으로 둔다. 지금 밝은 테마는 `--paper` 2.58:1, `--tint` 2.34:1이고, 어두운 테마는 2.71:1과 2.47:1이다.
- **계열 색:** `--s1`은 `--accent`와 같은 값으로 둔다(강조색이자 캔들 하락색이다). `--s2`~`--s4`는 두 테마에서 `--paper`·`--tint`와 3:1 이상이어야 한다. 또 제2색각 모의 변환(Machado 2009 행렬) 뒤 계열 색 쌍마다 CIE76 색차(색 공간에서 두 색의 거리)가 15 이상이어야 한다. 지금 `--s2`·`--s4` 색차는 밝은 테마 8.4, 어두운 테마 11.1이고, 밝은 `--s4`는 `--tint`에서 2.95:1이다.
- **보조 글자색:** `--ink-3`를 밝은 테마 `--tint`에서 4.5:1 이상으로 바꾼다. 지금은 4.39:1이다.

## 페이지 틀

페이지 틀의 결함은 다음과 같이 고친다. 페이지 전환 동작만 템플릿 스크립트로 고치고, 나머지는 CSS로 고친다.

- **페이지 번호:** 스크립트가 도는 페이지형 문서(`.js`)에서는 화면에 페이지 넘김 막대의 번호만 보이게 한다. 본문 첫 줄 `.pno`는 `.js` 상태의 화면에서만 숨긴다. 스크립트가 없거나 인쇄할 때는 `.pno`를 보인다.
- **주소 앵커 이동:** `template-paged.html`의 페이지 전환 코드가 `hashchange`를 받아, 주소 끝이 `#pN`으로 바뀌면 N페이지를 보인다. `#pN` 모양이 아닌 앵커는 무시한다.
- **용어 목록:** `.gloss`의 각 항목에서 용어와 풀이를 가까이 붙인다. 용어 열의 폭은 내용 폭과 14em 중 작은 값으로 두고, 그보다 긴 용어는 줄을 바꾼다. 390 폭에서는 용어 아래에 풀이가 온다. 목록 위에 CSS로 '용어' 머리글을 보인다.
- **넓은 표:** 390 폭에서 표 셀의 최소 폭을 56px로 확보하고, 넘치는 표는 스크롤 상자(`.tbl`) 안에서 가로로 민다. 4열 이상 표가 든 스크롤 상자에는 760px 이하 화면에서 '옆으로 밀어 볼 수 있습니다' 단서를 CSS로 보인다. 4열 이상 표는 `:has()` 선택자로 판정하고, 인쇄에서는 단서를 숨긴다. check.py의 서식 규칙(`checks/style.py`)이 그라데이션·그림자를 금지하므로 그림자 효과는 쓰지 않는다.

## 제목 틀

페이지형 보고서의 페이지 머리는 작은 절 이름, 결론 제목, 여러 줄 불릿의 순서다. 상위 설계의 제목 체계를 화면과 검사에 구현한다.

**표시.** 절 이름은 `<p class="sec">`로 쓰고 목차(`.toc`)의 링크 글과 같게 둔다. 결론 제목은 `<h2>`로 쓴다. 그 아래 불릿은 지금의 `ul.pts`다. 결론이 없는 페이지(요약, `page list`인 절차·목록·부록)는 `.sec` 없이 지금처럼 명사구 `<h2>`만 둔다. `template-paged.html`의 견본 페이지를 이 형식으로 고친다.

**검사.** `checks/style.py`에 결론 제목 검사를 별도 규칙 함수로 추가한다. 이 규칙은 `<p class="sec">`가 있는 `section.page`의 직계 `h2`에만 적용한다. 그런 `h2`는 공백 포함 40자 이하이고 문장 어미로 끝나야 한다. 같은 `h2`는 기존 명사구 검사에서 뺀다. `.sec`은 명사구 검사(18자 이하)를 받는다. `.sec`이 없는 기존 문서, 요약 상자(`.gist`)의 `h2`, 결론 없는 페이지의 `h2`는 지금처럼 명사구 검사를 받는다. 그러므로 기존 문서와 고정 견본은 이 변경으로 새 위반이 생기지 않는다.

**대조 방식.** 결론 제목 규칙은 `RULES`에 원본 대조 방식 `old`로 등록해, 원본을 받는 함수로 만든다. 기존 문서를 고칠 때 원본에 이미 있던 `h2`는 위반으로 세지 않는다. 본문 문장을 바꾸지 않는다는 수정 규칙(SKILL.md)과 부딪히지 않게 하기 위해서다.

**기준 규칙 검사.** L1의 공식 측정은 기준 커밋의 규칙으로도 함께 검사한다(`eval/gates.py --base-checks`). 기준 규칙은 `.sec` 페이지의 결론 `h2`를 명사구 위반으로 본다. 그래서 L1은 기준 규칙 결과에서 이 위반('라벨이 명사구가 아님' 가운데 `.sec` 페이지의 `h2`)만 제외한다. 그 밖의 기준 규칙 위반은 그대로 실패로 센다.

**문서.** `보고서-규격.md`의 구성 요소 규칙에 절 이름과 결론 제목 행을 추가한다. `SKILL.md`의 페이지 구성 규칙은 C3가 고친다. C3 병합 전까지는 두 문서가 다르게 말하지만, 상위 설계의 병합 순서(C2 → C1 → C3)와 통합 확인이 이 차이를 해소한다.

## C3용 화면 요소

C3의 내용 규칙은 C2가 정한 클래스와 CSS만 쓴다. 이 요소들은 다음과 같다.

| 요소 | 마크업 | 표시 |
|---|---|---|
| 바뀐 칸 | `td.chg` | 굵은 글과 보조 바탕. 보조 바탕은 `--tint`와 구분되는 값을 쓴다 |
| 확인 상태 | `<span class="state" data-state="run">실행으로 확인함</span>` | 글자는 작성자가 마크업에 쓴다(실행으로 확인함·추론함·가정함). `data-state`는 테두리 색 선택에만 쓴다 |
| 대체됨 배너 | `<div class="superseded"><b>대체됨</b> …</div>` | 기존 경고 문단(`.aside.warn`)과 같은 위 괘선과 굵은 머리말. 왼쪽 색 띠는 쓰지 않는다 |

확인 상태 글자를 CSS로 만들지 않는다. 그렇게 만든 글자는 검사기와 검토용 글 추출(`eval/shoot.py`)에 잡히지 않기 때문이다. 세 요소는 `template-paged.html` 견본에 한 번씩 넣어 대비를 측정받는다.

## 검증

L2는 아래 확인을 통과한 뒤 브랜치를 넘긴다. 병합 여부는 L1이 공식 측정으로 판정한다. 공식 측정에는 하락 금지와 판정 차례 3번이 적용되고, 기준 규칙 검사도 함께 한다.

1. **관리 블록 재빌드:** `report-base.css`를 고친 뒤 `python build.py template.html`과 `python build.py template-paged.html`을 실행한다.
2. **기계 판정(고정 견본):** `python eval/rebuild.py <폴더>`로 다시 빌드한 고정 견본에서 `python eval/gates.py <html>… --only layout`이 통과한다. 고정 견본의 `hash-nav`는 기록만 하고 판정에 쓰지 않는다(gates.py의 기본 동작이다).
3. **기계 판정(템플릿):** `python eval/gates.py template.html template-paged.html --only layout --judge-hash-nav`가 통과한다.
4. **규칙 검사:** `python check.py template.html`과 `python check.py template-paged.html`이 위반 0건이다.
5. **단위 시험:** `python -B -m unittest discover -s tests`가 통과한다. 시험 대상은 아래 두 가지다.
   - **결론 제목 검사가 적용되는 입력:** `.sec` 페이지의 결론 `h2`는 통과한다. 40자 초과이거나 문장 어미가 없으면 위반이다. `.sec` 자체의 명사구 검사도 시험한다.
   - **결론 제목 검사가 적용되지 않는 입력:** `.sec`이 없는 페이지형 문서, `.gist`의 '요약', `page list`의 `h2`에는 결론 제목 검사가 걸리지 않는다. 원본에 있던 `h2`도 위반으로 세지 않는다.
6. **자가 점검:** 템플릿 두 개와 다시 빌드한 고정 견본을 `eval/shoot.py`로 찍는다. 그 출력만 받은 서브에이전트가 체크리스트 `layout` 항목을 검토한다. 한 차례는 검토 3회의 다수결이고, 충족률이 85% 이상이어야 한다. 이 차례는 3번까지 하고, 세 번째에도 기준에 못 미치면 리포트에 적고 작업을 끝낸다.

## 함정

이 컴포넌트에서 막히기 쉬운 지점은 다음과 같다.

- **문서 스크립트의 위치:** 페이지 전환 스크립트는 관리 블록 밖의 문서 코드다. 고정 견본에는 CSS 변경만 들어가고 이 스크립트 변경은 들어가지 않는다.
- **금지 서식:** `checks/style.py`가 그라데이션·그림자·둥근 모서리·왼쪽 색 띠·토큰 밖 색 리터럴을 금지한다.
- **토큰을 함께 쓰는 곳:** `report-charts.js`가 `--accent-2`를 ECharts 다섯째 계열 색과 지나온 도형 테두리에, `--s1`을 캔들 하락색에 쓴다. 토큰 값만 바꾸고 이름은 그대로 둔다.
- **숨은 페이지:** 페이지형 문서에서 보이지 않는 페이지의 요소는 폭이 0이다. 폭을 재는 규칙을 스크립트로 만들지 않고 CSS로 해결한다.

## 산출 계약

C2의 L2는 브랜치까지만 만들고 병합·push하지 않는다. plan 마지막 줄에는 리뷰 마커(`<!-- spec-review: passed -->` 또는 `escalated`)를 남긴다. 리포트는 저장소 밖 스크래치 경로에 쓰고 브랜치에 커밋하지 않는다. 리포트에는 다음을 적는다.

- 변경 파일과 시험 결과
- 바꾼 토큰의 이전·이후 값과 대비·색차
- 고정 견본·템플릿의 기계 판정 결과
- 체크리스트 자가 점검 결과
- plan 리뷰에서 기능적 변화가 있었던 반영
- 상위 설계와 다르게 정한 점
- 브랜치 이름

# 보고서 시각화 확장 설계

작성일 2026-09-28 · 대상 스킬 `writing-html-reports`

## 목적과 범위

이 설계는 `writing-html-reports`로 만드는 HTML 문서가 내용에 맞는 차트·도식·단계 재생 애니메이션을 스스로 고르게 하고, 그 결과가 기존 금융 보고서 규격을 지키게 한다. 지금 스킬은 도표의 형식만 정하고, 근거 조건을 표 하나로도 충족할 수 있어 모델이 시각화 없이 표로 끝낼 수 있다.

사용자가 정한 조건은 다음과 같다.

- **대상 시각화:** 데이터 플로우, 설계 구조, 데이터 구조, 동작 예시, 파이 차트, 시계열 차트(이동평균선 포함)를 다룬다.
- **도구:** 수치 차트는 ECharts, 도식은 Mermaid, 동작 예시는 GSAP로 그린다.
- **열람 환경:** 인터넷이 되는 곳에서만 열므로 라이브러리는 jsDelivr CDN에서 로드한다.
- **재생 방식:** 동작 예시는 조작 버튼으로 넘기는 단계 재생형으로 만들고, 자동 반복은 쓰지 않는다.
- **적용 강도:** 선택 기준표와 완료 전 자가 점검으로 유도하고, `check.py`로 시각화를 강제하지 않는다.
- **공유 방식:** 테마와 재생 함수는 `build.py`가 BEGIN/END 표시 사이에 삽입한다.

기존 규격(흰 바탕, 1px 선, 직각, 토큰 색, 한 가지 강조색, 장식 금지)은 그대로 유지한다. 움직임 금지는 동작 예시 도표 안에서만 푼다.

## 구성 요소

새 파일은 `report-charts.js` 하나이고, 나머지는 기존 파일을 고친다.

| 파일 | 변경 | 역할 |
|---|---|---|
| `report-charts.js` | 신규 | 규격 테마 등록, `RC.chart`·`RC.ma`·`RC.demo` 함수, Mermaid 초기화 |
| `build.py` | 수정 | CSS 표시에 이어 `/* BEGIN report-charts */ … /* END report-charts */` 표시 사이를 `report-charts.js`로 다시 채운다. 이 표시가 없는 문서는 JS 삽입을 생략한다 |
| `report-base.css` | 수정 | `.viz`(차트 상자, 기본 높이 320px), `.demo-ctl`(조작 줄), `.demo-cap`(단계 설명 줄), 인쇄용 단계 목록 스타일을 추가한다 |
| `template.html`, `template-paged.html` | 수정 | CDN `<script>` 세 줄, BEGIN/END report-charts 표시, 차트·도식·동작 예시 견본 하나씩을 추가한다 |
| `SKILL.md`, `보고서-규격.md` | 수정 | 시각화 지시와 선택 기준표, 규격 행 수정 |
| `check.py` | 수정 | 스크립트 관련 규칙 추가, 움직임 규칙 범위 조정 |
| `tests/` | 신규 | `test_check.py`, `sample-viz.html` |

CDN 주소는 정확한 버전 번호로 고정한다. 버전을 고정해야 라이브러리가 바뀌어도 이미 배포한 문서의 모양이 유지된다.

| 라이브러리 | 버전 | 선택 이유 |
|---|---|---|
| ECharts | 6.1.0 | 2026-09-28 기준 npm 최신 안정 버전 |
| Mermaid | 11.17.2 | 12.0.0은 2026-09-10에 나온 새 주 버전이라 API 변경 위험이 있다. 11 계열의 마지막 버전(2026-08-25)을 쓴다 |
| GSAP | 3.15.0 | npm 최신 안정 버전 |

## report-charts.js 인터페이스

문서 작성자(모델)는 아래 함수와 표기만 알면 되고, 테마의 세부 내용은 알 필요가 없다.

- **`RC.chart(요소, 옵션)`:** ECharts를 SVG 렌더러로 초기화하고 옵션을 적용한 인스턴스를 돌려준다. 규격 테마가 자동 적용된다. 테마의 색은 `--s1`~`--s4`·`--accent`·`--ink`·`--rule`을 CSS 변수에서 읽으므로 다크 모드를 따라간다. 막대는 직각이고, 그림자와 진입 애니메이션(`animation:false`)은 끄고, 툴팁은 켠다.
- **`RC.color(이름)`:** 토큰 이름(`'s1'`, `'accent'`, `'neg'` 등)을 받아 현재 테마의 색 값을 돌려준다. 문서 스크립트는 색 리터럴 대신 이 함수를 쓴다.
- **`RC.ma(값 배열, n)`:** n개 이동평균 배열을 돌려준다. 앞의 n−1개는 `null`이다.
- **`<pre class="mermaid">`:** 이 요소 안에 Mermaid 텍스트를 적으면 페이지를 열 때 규격 테마 변수(1px 선, 흰 바탕, 토큰 색, Pretendard)로 그린다. 따로 호출할 함수는 없다.
- **`RC.demo(figure 요소, 단계 배열)`:** GSAP 타임라인으로 단계 재생을 만든다. 단계 배열의 항목은 `{name, text, play}`이고, `play(tl)`은 그 단계의 전환을 타임라인 `tl`에 추가한다. 함수는 단계마다 타임라인 라벨을 만들고 조작 버튼(이전·재생/일시정지·다음·처음부터), `2/3` 형식의 단계 표시, 설명 줄을 figure 안에 만든다.

`RC.demo`의 동작 조건은 세 가지다.

- **움직임 줄이기 설정:** `prefers-reduced-motion: reduce`이면 전환 없이 단계의 끝 상태로 바로 이동한다.
- **인쇄:** `beforeprint`에서 마지막 단계로 이동하고, 인쇄용 CSS가 단계 설명 목록 전체를 펼친다.
- **자동 반복 금지:** `repeat`·`yoyo`를 쓰지 않는다.

## 지시 문서 변경

`SKILL.md`에 '시각화' 절을 새로 두고, 근거가 기준표의 내용 유형에 해당하면 표 대신 또는 표와 함께 해당 시각화를 쓰라고 지시한다. 기준표는 다음과 같다.

| 내용 유형 | 시각화 | 도구 | 쓰지 않는 조건 |
|---|---|---|---|
| 기간에 따른 값 변화(시계열) | 선 차트와 이동평균선 | ECharts + `RC.ma` | 시점이 4개 미만이면 표로 쓴다 |
| 시가·고가·저가·종가 | 캔들 차트와 거래량 막대 | ECharts | 해당 없음 |
| 전체 중 구성비 | 파이(도넛) | ECharts | 항목이 6개를 넘거나 비율이 비슷하면 가로 막대로 쓴다 |
| 항목 간 크기 비교 | 가로 막대 | ECharts 또는 기존 `.bars` | 값이 2~3개면 핵심 수치 줄(`.keyfig`)로 쓴다 |
| 두 변수의 관계 | 산점도 | ECharts | 해당 없음 |
| 데이터 흐름과 처리 단계 | 플로우 차트 | Mermaid `flowchart` | 해당 없음 |
| 모듈과 시스템 구조 | 블록 다이어그램 | Mermaid `flowchart` + `subgraph` | 해당 없음 |
| 주체 간 호출 순서 | 시퀀스 다이어그램 | Mermaid `sequenceDiagram` | 해당 없음 |
| 데이터 구조와 테이블 관계 | 클래스·ER 다이어그램 | Mermaid `classDiagram`·`erDiagram` | 해당 없음 |
| 상태 전이 | 상태 다이어그램 | Mermaid `stateDiagram` | 해당 없음 |
| 처리 과정의 동작 예시 | 단계 재생 | Mermaid 또는 SVG + `RC.demo` | 3단계 미만이면 정지 도식으로 쓴다 |

기준표 아래에는 공통 규칙 세 가지를 둔다.

- **정확한 값 보존:** 독자가 값을 조회해야 하는 자료는 차트 아래에 표를 함께 둔다.
- **도표 구성:** 차트·도식·동작 예시 모두 기존 `figure` 구성(제목, 단위·기간, 본체, 출처 줄)과 `LABEL-NOUN`을 따른다.
- **장식 금지:** 3D, 그림자, 계열마다 채도 높은 색, 진입 애니메이션을 쓰지 않는다. 움직임은 `RC.demo` 안에서만 쓴다.

`SKILL.md` 완료 기준에는 두 가지를 추가한다.

- **시각화 점검:** 표로만 둔 근거 중 기준표에 해당하는 표가 있으면 도표로 바꾸거나, 바꾸지 않은 이유를 보고에 적는다.
- **스크린샷 대기:** 차트가 그려진 뒤 캡처하도록 `--virtual-time-budget`을 8000으로 늘린다.

기존 HTML 수정 작업에는 '본문 문장과 숫자를 바꾸지 않는다'는 조건이 있으므로 도표를 자동으로 추가하지 않는다. 기준표에 해당하는 표는 보고에서 '도표로 바꿀 수 있는 표' 목록으로만 알린다.

`보고서-규격.md`는 세 행을 고친다.

- **도표:** 'ECharts 규격 테마(`RC.chart`)로 그린다'를 추가한다.
- **도식(SVG):** 'Mermaid 규격 테마 또는 직접 그린 SVG'로 고친다.
- **움직임:** '동작 예시(`figure.demo`)의 단계 재생만 허용한다. 조작 버튼이 있어야 하고 자동 반복은 쓰지 않는다'로 고친다. 스크롤 효과와 장식용 hover 금지는 유지한다.

## 검사기 변경

`check.py`는 실행 전 HTML 원문만 읽으므로, 스크립트 원문에서 찾을 수 있는 위반만 추가한다. 이 절에서 '문서 스크립트'는 BEGIN/END report-charts 표시 밖의 `<script>` 내용을 말한다.

| 규칙 | 변경 | 검출 내용 |
|---|---|---|
| 움직임 | 수정 | BEGIN/END report-charts 사이를 검사에서 뺀다. 표시 밖 CSS의 움직임 금지는 그대로 둔다 |
| 근거 인정 | 수정 | 근거로 인정하는 요소에 `class="mermaid"`와 `class="viz"`를 추가한다 |
| 허용 밖 스크립트 | 신규 | `cdn.jsdelivr.net/npm/`의 `echarts`·`mermaid`·`gsap` 밖에서 로드한 `<script src>` |
| 버전 미고정 | 신규 | 허용 라이브러리 주소에 `x.y.z` 형식의 정확한 버전이 없는 주소 |
| 동작 예시 밖 애니메이션 | 신규 | 문서 스크립트의 `gsap.` 직접 호출, `repeat:-1`, `yoyo` |
| 차트 장식 | 신규 | 문서 스크립트의 `shadowBlur`, 1 이상의 `borderRadius`, `animation:true` |
| 스크립트 안 색 리터럴 | 신규 | 문서 스크립트의 `#xxx`·`#xxxxxx` 색 |

ECharts 옵션 안의 제목·축 이름·범례 글자는 JS 문자열이라 라벨·금지어 검사 대상이 아니다. 이 글자는 스크린샷으로 확인한다. Mermaid 글자는 HTML 텍스트이므로 기존 금지어 검사에 포함된다.

## 페이지형 문서 처리

페이지형 템플릿은 현재 페이지 밖을 `display:none`으로 숨기므로(`report-base.css:124`), 숨은 요소의 폭 0을 `report-charts.js` 안에서 처리한다. 기존 페이지 넘김 코드(`show()`)는 고치지 않는다.

- **ECharts:** 초기화할 때 요소 폭이 0이면 `main.doc` 폭으로 그린다. 높이는 `.viz`의 CSS 높이를 쓰고, `data-h` 속성이 있으면 그 값을 쓴다. `ResizeObserver`가 요소 폭 변화를 감지해 크기를 다시 맞춘다.
- **Mermaid:** `mermaid.render()`로 SVG 문자열을 만든 뒤 요소에 넣는다. 이 함수는 측정용 임시 요소를 따로 만들므로 숨은 페이지에서도 배치가 정상이라고 가정한다. 이 가정은 구현 첫 단계에서 검증한다.
- **동작 예시:** `ResizeObserver`가 폭 0을 감지하면 일시정지하고, 돌아오면 멈춘 단계에서 이어 본다.
- **인쇄:** 인쇄할 때는 모든 페이지가 펼쳐진다(`report-base.css:153`). 동작 예시는 앞 절의 인쇄 조건을 따른다. ECharts SVG가 A4 폭을 넘으면 `beforeprint`에서 인쇄 폭으로 크기를 다시 맞춘다.

단일 페이지 템플릿(`template.html`)은 페이지를 숨기지 않으므로 같은 코드가 그대로 동작한다.

## 검증 방법

검증은 다섯 층으로 하고, 층마다 입력과 기대 결과를 정한다.

| 검증 층 | 입력 | 기대 결과 |
|---|---|---|
| 가정 확인 | 숨은 페이지(`p2`)에 Mermaid 도식 하나를 둔 최소 HTML | `#p2`로 연 스크린샷에서 도식 배치가 정상이다. 실패하면 Mermaid 방식을 '페이지가 보일 때 그리기'로 바꾸고 사용자에게 알린다 |
| 검사기 단위 시험 | `tests/test_check.py`(표준 라이브러리 `unittest`), 새 규칙마다 위반 견본과 정상 견본 | 위반 견본은 해당 규칙으로 검출되고 정상 견본은 0건이다. 두 템플릿도 0건이다 |
| build.py | 차트 표시가 있는 문서와 없는 문서 | 두 번 실행한 결과가 같다. 표시가 없는 문서는 CSS만 채워진다 |
| 렌더링 | `tests/sample-viz.html`(시계열과 이동평균선, 파이, 플로우 차트, 시퀀스 다이어그램, 동작 예시) | 페이지별 헤드리스 Edge 스크린샷에서 규격 색·직각·출처 줄을 지키고 빈 차트가 없다. `data-theme="dark"` 사본도 같다 |
| 인쇄 | 같은 견본의 헤드리스 Edge `--print-to-pdf` 출력 | 차트가 용지 폭 안에 있고, 동작 예시가 마지막 단계와 단계 설명 목록으로 인쇄된다 |

스킬 동작 시험은 서브에이전트 하나로 한다. 수정된 스킬 경로와 다음 요청만 주고, 시각화 지시는 주지 않는다: "월별 거래대금 12개월 자료와 주문 처리 흐름(접수→검증→체결→정산)을 정리한 검토 자료". 시계열 차트(이동평균선 포함)와 플로우 차트나 동작 예시가 자발적으로 들어가고 `check.py`가 위반 0건이면 통과다. 실패하면 `SKILL.md` 문안을 고친 뒤 같은 시험을 다시 실행한다.

# 보고서 시각화 확장 설계

작성일 2026-09-28 · 대상 스킬 `writing-html-reports`

## 목적과 범위

이 설계는 모델이 페이지 내용에 맞는 시각화를 스스로 고르고, 그 시각화가 기존 금융 보고서 규격을 지키게 한다. 대상 문서는 `writing-html-reports`로 만드는 HTML 문서다. 이 설계에서 '시각화'는 차트(ECharts), 도식(Mermaid 또는 직접 그린 SVG), 동작 예시(단계별로 넘겨 보는 애니메이션)를 묶은 이름이다.

지금 스킬은 시각화의 형식만 정한다. 또 `check.py`의 근거 조건은 페이지마다 표·`figure`·SVG·핵심 수치 줄 중 하나가 있기만 하면 충족된다. 그래서 모델이 시각화 없이 표 하나로 페이지를 끝낼 수 있다.

사용자가 정한 조건은 다음과 같다.

- **대상 시각화:** 데이터 플로우, 설계 구조, 데이터 구조, 동작 예시, 파이 차트, 시계열 차트(이동평균선 포함)를 기본으로 다룬다. 사용자가 "등등등 다양한 시각화 도구"라고 했으므로 같은 도구로 그릴 수 있는 인접 유형도 기준표에 포함한다.
- **도구:** 차트는 ECharts, 도식은 Mermaid, 동작 예시는 GSAP로 그린다.
- **열람 환경:** 인터넷이 되는 곳에서만 열므로 라이브러리는 jsDelivr CDN에서 로드한다.
- **재생 방식:** 동작 예시는 조작 버튼으로 넘기는 단계 재생형으로 만들고, 자동 반복은 쓰지 않는다.
- **적용 강도:** 선택 기준표와 완료 전 자가 점검으로 유도하고, `check.py`로 시각화를 강제하지 않는다.
- **공유 방식:** 테마와 연결 코드는 `build.py`가 BEGIN/END 표시 사이에 삽입한다.
- **적용 작업:** 시각화 추가는 새 문서 작성에만 적용한다.

기존 규격(흰 바탕, 1px 선, 직각, 토큰 색, 한 가지 강조색, 장식 금지)은 그대로 유지한다. 움직임 금지는 동작 예시 안에서만 푼다.

## 구성 요소

새 파일은 `report-charts.js`와 시험 파일 두 개이고, 나머지는 기존 파일을 고친다.

| 파일 | 변경 | 변경 내용 |
|---|---|---|
| `report-charts.js` | 신규 | 규격 테마 등록, `RC.chart`·`RC.color`·`RC.ma`·`RC.demo` 함수, Mermaid 렌더를 제공한다 |
| `build.py` | 수정 | report-charts 표시 사이를 `report-charts.js`로 다시 채우고, 버전이 다르면 멈춘다 |
| `report-base.css` | 수정 | 차트 상자와 동작 예시 조작 줄과 인쇄 규칙을 추가한다 |
| `template.html`, `template-paged.html` | 수정 | CDN 태그와 report-charts 표시와 시각화 견본을 추가한다 |
| `SKILL.md` | 수정 | 시각화 절과 완료 기준과 흔한 실수를 고친다 |
| `보고서-규격.md` | 수정 | 규격 행 세 개와 검출 목록을 고친다 |
| `check.py` | 수정 | 움직임 규칙 범위를 좁히고 스크립트·Mermaid 규칙을 추가한다 |
| `tests/test_check.py` | 신규 | 검사 규칙마다 위반 견본과 정상 견본을 판정한다 |
| `tests/sample-viz.html` | 신규 | 페이지형 견본으로 렌더링·동작·인쇄를 시험한다 |

CDN 주소는 정확한 버전 번호로 고정한다. 주소를 고정하면 라이브러리가 새로 나와도 이미 배포한 문서의 모양이 유지된다. 버전을 고를 때는 출시 뒤 한 달이 지나지 않은 주 버전을 피한다. 세 주소는 2026-09-28에 이 PC에서 모두 200으로 응답했다.

| 라이브러리 | 버전 | 선택 이유 |
|---|---|---|
| ECharts | 6.1.0 | 6.0.0이 2025-07-30에 나와 주 버전이 안정되었고, 6.1.0이 최신 안정 버전이다 |
| Mermaid | 11.17.2 | 12.0.0이 2026-09-10에 나와 한 달이 지나지 않았으므로 11 계열의 마지막 버전을 쓴다 |
| GSAP | 3.15.0 | 3 계열이 오래 유지되었고, 3.15.0이 최신 안정 버전이다 |

## 스크립트 배치

스크립트는 세 층으로 나뉘고, 실행 순서는 라이브러리, 연결 코드, 문서 스크립트다. '연결 코드'는 build.py가 삽입하는 `report-charts.js` 내용이고, '문서 스크립트'는 모델이 문서마다 쓰는 `<script>`다.

- **라이브러리:** CDN `<script src>` 세 줄을 `<head>`에 `defer` 없이 둔다.
- **연결 코드:** 라이브러리 태그 바로 뒤에 별도 `<script>`를 두고, 그 안에 `/* BEGIN report-charts echarts@6.1.0 mermaid@11.17.2 gsap@3.15.0 */`와 `/* END report-charts */` 표시를 둔다. 기존 페이지 넘김 `<script>`와는 섞지 않는다.
- **문서 스크립트:** `</main>` 바로 뒤에 둔다. 이 위치에서는 차트 상자가 이미 만들어져 있다.

build.py는 BEGIN 표시에 적힌 버전과 문서의 CDN 주소 버전을 대조한다. 다르면 채우지 않고 문서 이름과 두 버전을 출력한 뒤 종료 코드 1로 멈춘다. 연결 코드를 새 라이브러리에 맞춰 고친 뒤 옛 문서에 build.py를 실행해도, 옛 라이브러리와 새 연결 코드가 섞이지 않게 하기 위해서다. report-charts 표시가 없는 문서는 CSS만 채운다.

## 연결 코드 인터페이스

모델은 아래 네 함수와 Mermaid 표기만 알면 되고, 테마의 세부 내용은 알 필요가 없다.

- **`RC.chart(상자, 옵션)`:** `.viz` 상자에 ECharts를 SVG 렌더러로 그리고 인스턴스를 돌려준다.
- **`RC.color(이름)`:** 토큰 이름(`'s1'`, `'accent'`, `'neg'` 등)에 해당하는 현재 색 값을 돌려준다.
- **`RC.ma(값 배열, n)`:** n개 이동평균 배열을 돌려주고, 앞의 n−1개는 `null`로 채운다.
- **`RC.demo(figure, 단계 배열)`:** GSAP 타임라인으로 동작 예시를 만든다.
- **`<pre class="mermaid">`:** 이 안에 Mermaid 텍스트를 적으면 연결 코드가 그린다.

`RC.chart`가 등록하는 규격 테마는 문서를 열 때 CSS 변수(`--s1`~`--s4`, `--accent`, `--ink`, `--rule`)에서 색을 읽는다. 그래서 차트는 문서를 열 때의 밝은 모드나 다크 모드를 따르고, 열람 중에 테마가 바뀌면 따라가지 않는다. 테마는 막대를 직각으로 그린다. 그림자와 진입 애니메이션은 끄고 툴팁은 켠다. 차트 상자의 높이는 `.viz`의 CSS 높이(기본 320px)를 쓰고, 바꿀 때는 문서 전용 CSS로 바꾼다.

`RC.demo`의 단계 배열 항목은 `{name, text, play}`다. `play(tl)`은 그 단계의 전환을 타임라인 `tl`에 `tl.to`·`tl.set`으로 추가하고, `gsap.`을 직접 호출하지 않는다. `RC.demo`는 figure에 `demo` 클래스를 붙이고 무대 아래에 세 요소를 만든다. 조작 줄(`.demo-ctl`: 이전·재생/일시정지·다음·처음부터 버튼과 `2/3` 형식의 단계 표시), 현재 단계 설명 줄(`.demo-cap`), 전체 단계 설명 목록(`ol.demo-steps`, 화면에서는 숨김)이다.

동작 예시는 키 입력을 처리하지 않는다. 페이지형 템플릿의 화살표 키 페이지 넘김과 겹치지 않게 하기 위해서다. 브라우저에 움직임 줄이기 설정(`prefers-reduced-motion: reduce`)이 켜져 있으면 전환 없이 각 단계의 끝 상태로 바로 이동한다. 자동 반복(`repeat`, `yoyo`)은 쓰지 않는다.

Mermaid는 `startOnLoad:false`로 초기화해 자동 렌더를 끈다. 연결 코드는 `document.fonts.ready` 뒤에 `pre.mermaid`마다 `mermaid.render()`를 호출하고, 돌려받은 SVG로 그 `pre`의 내용을 바꾼다. 글꼴이 로드된 뒤 그려야 노드 상자 크기가 Pretendard 글자 폭에 맞는다. 테마 변수는 1px 선, 흰 바탕, 토큰 색, Pretendard로 정한다.

라이브러리 로드가 실패하면 연결 코드는 해당 라이브러리를 쓰는 시각화만 생략한다. 생략한 상자에는 "시각화를 불러오지 못했습니다" 한 줄을 넣고 나머지 시각화는 계속 그린다. 각 함수가 실행 전에 `typeof echarts`·`typeof mermaid`·`typeof gsap`을 확인하는 방식이다.

## 지시 문서 변경

`SKILL.md`에 '시각화' 절을 새로 두고, 근거가 기준표의 내용 유형에 해당하면 표 대신 또는 표와 함께 해당 시각화를 쓰라고 지시한다. 기준표는 다음과 같다.

| 내용 유형 | 시각화 | 도구 | 쓰지 않는 조건 |
|---|---|---|---|
| 기간에 따른 값 변화(시계열) | 선 차트와 이동평균선 | ECharts + `RC.ma` | 시점이 4개 미만이면 표로 쓴다 |
| 시가·고가·저가·종가 | 캔들 차트와 거래량 막대 | ECharts | 조건 없이 쓴다 |
| 전체 중 구성비 | 파이(도넛) 차트 | ECharts | 항목이 6개를 넘거나 비율이 비슷하면 가로 막대로 쓴다 |
| 항목 간 크기 비교 | 가로 막대 차트 | ECharts 또는 기존 `.bars`(CSS 막대 줄) | 값이 2~3개면 핵심 수치 줄(`.keyfig`)로 쓰고, 정확한 값 조회가 목적이면 표로 쓴다 |
| 두 변수의 관계 | 산점도 | ECharts | 조건 없이 쓴다 |
| 데이터 흐름과 처리 단계 | 플로우 차트 | Mermaid `flowchart` | 조건 없이 쓴다 |
| 모듈과 시스템 구조 | 블록 도식 | Mermaid `flowchart` + `subgraph` | 조건 없이 쓴다 |
| 주체 간 호출 순서 | 시퀀스 도식 | Mermaid `sequenceDiagram` | 조건 없이 쓴다 |
| 데이터 구조와 테이블 관계 | 클래스·ER 도식 | Mermaid `classDiagram`·`erDiagram` | 조건 없이 쓴다 |
| 상태 전이 | 상태 도식 | Mermaid `stateDiagram` | 조건 없이 쓴다 |
| 처리 과정의 동작 예시 | 동작 예시 | Mermaid 또는 SVG + `RC.demo` | 3단계 미만이면 정지 도식으로 쓴다 |

기준표 아래에는 공통 규칙을 둔다.

- **정확한 값 보존:** 독자가 값을 조회해야 하는 자료는 차트 아래에 표를 함께 둔다.
- **figure 구성:** 모든 시각화는 `figure` 안에 두고 기존 구성(제목, 단위·기간, 본체, 출처 줄)과 `LABEL-NOUN`을 따른다.
- **차트 제목 위치:** 차트 제목은 `figcaption .t`에만 쓰고, ECharts `title` 옵션은 쓰지 않는다.
- **도식 노드 모양:** Mermaid 노드는 직각 상자(`[텍스트]`)로 쓰고, 둥근 노드(`(텍스트)`, `([텍스트])`)와 `style`·`classDef` 색 지정은 쓰지 않는다.
- **장식 금지:** 3D, 그림자, 계열마다 채도 높은 색, 진입 애니메이션을 쓰지 않는다. 움직임은 `RC.demo` 안에서만 쓴다.

`SKILL.md` 완료 기준에는 세 가지를 추가한다.

- **시각화 점검(새 문서만):** 절의 결론이 추세·구성비·흐름·동작에 관한데 근거가 표뿐이면, 기준표의 시각화로 바꾸거나 바꾸지 않은 이유를 보고에 적는다.
- **시각화 글자 점검:** ECharts의 축 이름과 범례를 모아 읽어 명사구인지 확인한다.
- **스크린샷 대기:** 시각화가 그려진 뒤 캡처하도록 `--virtual-time-budget`을 8000으로 늘린다.

기존 HTML 수정 작업에는 '본문 문장과 숫자를 바꾸지 않는다'는 조건이 있으므로 시각화를 추가하지 않는다. 기준표에 해당하는 표는 보고에서 '시각화로 바꿀 수 있는 표' 목록으로만 알린다.

`SKILL.md`의 기존 문구도 두 곳 고친다. 완료 기준 1의 기대 출력에 연결 코드 반영 문구를 추가한다. 흔한 실수의 'BEGIN/END 안의 직접 수정' 항목에는 연결 코드의 원본이 `report-charts.js`라고 추가한다.

`보고서-규격.md`는 구성 요소 규칙 표의 세 행과 검출 목록 문단을 고친다.

- **도표 행:** 'ECharts 규격 테마(`RC.chart`)로 그린다'를 추가한다.
- **도식(SVG) 행:** 'Mermaid 규격 테마(직각 노드) 또는 직접 그린 SVG'로 고친다.
- **움직임 행:** '동작 예시(`RC.demo`)의 단계 재생만 허용한다'를 추가하고, 조작 버튼 필수와 자동 반복 금지를 적는다. 차트의 마우스오버 설명을 허용하는 기존 문장과 스크롤 효과·장식용 hover 금지는 유지한다.
- **검출 목록 문단:** 아래 '검사기 변경'의 새 규칙과 움직임 범위 변경을 반영한다.

## 검사기 변경

`check.py`는 실행 전 HTML 원문만 읽으므로, 원문에서 찾을 수 있는 규칙만 추가한다. 검사 대상은 세 가지 원문이다. CSS(`<style>`과 `style=""`), 문서 스크립트(report-charts 표시 밖의 `<script>`), Mermaid 원문(`pre.mermaid`의 텍스트)이다.

| 규칙 | 변경 | 검출 대상 |
|---|---|---|
| 움직임 | 수정 | CSS의 `@keyframes`·`transition`·`animation`과 문서 전체의 `IntersectionObserver` |
| 차트 애니메이션 | 신규 | 문서 스크립트의 `animation: true` |
| 허용 밖 스크립트 | 신규 | jsDelivr `npm/`의 `echarts`·`mermaid`·`gsap` 밖을 가리키는 `<script src>`·`import … from`·`import()` 주소 |
| 버전 미고정 | 신규 | 허용 라이브러리 주소 중 `x.y.z` 형식의 버전이 없는 주소 |
| GSAP 직접 호출 | 신규 | 문서 스크립트의 `gsap.` 호출과 `repeat`·`yoyo` 설정(콜론 앞뒤 공백 허용) |
| 차트 장식 | 신규 | 문서 스크립트의 `shadowBlur`와 3 이상의 `borderRadius` |
| 스크립트·도식 색 리터럴 | 신규 | 문서 스크립트와 Mermaid 원문의 `#xxx`·`#xxxxxx` 색, Mermaid 원문의 `style`·`classDef` 줄 |
| 스크립트 글자 금지어 | 신규 | 문서 스크립트의 따옴표 문자열 안 금지어 |

움직임 규칙을 CSS로 좁힌 이유는 기존 정규식이 HTML 전체를 검사해 문서 스크립트의 `animation:false`까지 위반으로 검출하기 때문이다. `borderRadius` 임계값은 기존 CSS·SVG 규칙과 같은 3으로 맞춘다. GSAP 직접 호출 규칙의 메시지는 '`play(tl)` 안에서는 `tl.to`·`tl.set`을 쓴다'로 적는다. 스크립트 글자 금지어는 기존 `banned_hits`를 그대로 쓰고, 추출 정규식 하나만 추가한다.

근거 조건은 바꾸지 않는다. 모든 시각화를 `figure` 안에 두므로 기존 정규식의 `<figure`가 이미 근거로 인정한다.

검사하지 못하는 항목도 있다. ECharts 축 이름·범례의 명사구 여부는 완료 기준의 시각화 글자 점검으로 확인한다. Mermaid 노드의 둥근 모양은 흐름도와 시퀀스 도식의 괄호 표기를 정규식으로 구분할 수 없어 검사하지 않고, 스크린샷으로 확인한다.

## 페이지형 문서 처리

페이지형 템플릿은 현재 페이지 밖을 `display:none`으로 숨기므로(`report-base.css:124`), 연결 코드가 숨은 페이지의 폭 0을 처리한다. 기존 페이지 넘김 코드(`show()`)는 고치지 않는다.

ECharts는 차트 상자의 폭이 0이면 `main.doc` 폭으로 처음 그린다. 이어서 `ResizeObserver`(요소 크기 변화를 알려 주는 브라우저 기능)가 차트 상자의 폭 변화를 감지해 크기를 다시 맞춘다.

Mermaid의 `mermaid.render()`는 측정용 임시 요소를 `body`에 따로 만들어 쓴다. 그래서 숨은 페이지의 `pre.mermaid`도 올바른 크기로 그린다고 가정한다. 이 가정은 구현 첫 단계에서 검증한다.

동작 예시는 `ResizeObserver`가 figure의 폭 0을 감지하면 일시정지한다. 페이지로 돌아와도 자동으로 재생하지 않고, 멈춘 단계에서 사용자가 버튼으로 이어 본다.

단일 페이지 템플릿(`template.html`)은 페이지를 숨기지 않으므로 같은 코드가 폭 0 처리 없이 동작한다.

## 인쇄

인쇄 상태는 CSS로 정하고, 이벤트 처리는 보조로 둔다. 헤드리스 Edge의 PDF 출력에서 `beforeprint`가 발생하는지 확인되지 않았기 때문이다.

- **인쇄용 CSS:** `@media print`에서 동작 예시의 조작 줄과 설명 줄을 숨기고 `ol.demo-steps`를 펼친다. `.viz svg`에는 `max-width:100%`를 준다.
- **보조 처리:** `beforeprint`에서 동작 예시를 마지막 단계로 옮기고 차트를 인쇄 폭(A4 본문 약 688px)으로 다시 맞춘다. `afterprint`에서 차트 크기와 동작 예시 단계를 되돌린다.

`beforeprint`가 헤드리스 PDF 출력에서 발생하는지는 가정 확인 층에서 측정한다. 발생하지 않으면 인쇄용 CSS만으로 PDF 결과가 기대 결과를 충족하는지 확인한다.

## 검증 방법

검증은 여섯 층이다. 브라우저 동작은 Playwright(브라우저 자동화 도구)로 조작하고 확인한다.

| 검증 층 | 입력 | 기대 결과 |
|---|---|---|
| 가정 확인 | 숨은 페이지(`p2`)와 `p1`에 같은 Mermaid 도식을 둔 최소 HTML | `#p2`에서 그린 도식 SVG의 폭과 높이가 `p1` 도식과 같고, 노드 글자가 상자 밖으로 넘치지 않는다. 같은 파일을 헤드리스 Edge PDF로 출력해 `beforeprint` 발생 여부를 기록한다 |
| 검사기 단위 시험 | `tests/test_check.py`(표준 라이브러리 `unittest`), 수정 규칙과 신규 규칙마다 위반 견본과 정상 견본 | 위반 견본은 해당 규칙으로 검출되고 정상 견본은 0건이다. 두 템플릿과 `sample-viz.html`도 0건이다 |
| build.py 시험 | 연결 코드 표시가 있는 문서, 표시가 없는 문서, CDN 버전이 다른 문서 | 두 번 실행한 결과가 같다. 표시가 없는 문서는 CSS만 채워진다. 버전이 다른 문서에서는 종료 코드 1로 멈춘다 |
| 렌더링 시험 | `tests/sample-viz.html`(페이지형 템플릿에서 만든 견본: 시계열과 이동평균선, 파이, 플로우 차트, 시퀀스 도식, 동작 예시) | 페이지마다 캡처한 스크린샷에서 규격 색·직각·출처 줄을 지키고 빈 차트가 없다. `data-theme="dark"` 사본도 같다 |
| 동작 시험 | 같은 견본을 Playwright로 조작 | `RC.ma([1,2,3,4],2)`가 `[null,1.5,2.5,3.5]`다. `p2`로 넘긴 뒤 숨어 있던 차트의 SVG 폭이 차트 상자 폭과 같다. 다음 버튼을 두 번 누르면 단계 표시가 `3/3`이다. 재생 중 다른 페이지로 넘겼다 돌아오면 일시정지 상태다. 움직임 줄이기 설정을 켜면 다음 버튼 직후 끝 상태다 |
| 인쇄 시험 | 같은 견본의 헤드리스 Edge PDF 출력 | 차트가 용지 폭 안에 있고, 동작 예시 대신 단계 설명 목록 전체가 인쇄된다 |

스킬 동작 시험은 서브에이전트 하나로 한다. 서브에이전트에는 수정된 스킬 경로와 다음 요청만 주고, 시각화 지시는 주지 않는다. 요청은 "월별 거래대금 12개월 자료와 주문 처리 흐름(접수→검증→체결→정산)을 정리한 검토 자료"다. 통과 조건은 네 가지다.

- **시계열:** 시계열 차트와 이동평균선이 들어간다.
- **흐름:** 플로우 차트나 동작 예시가 들어간다.
- **과시각화 없음:** 기준표에 해당하지 않는 표를 시각화로 바꾸지 않는다.
- **검사기:** `check.py` 결과가 위반 0건이다.

실패하면 `SKILL.md` 문안을 고친 뒤 같은 시험을 다시 실행한다. 두 번 실패하면 멈추고 사용자에게 결과를 보고한다.

- **로드 실패:** 라이브러리 하나의 실패가 다른 시각화로 번지지 않게 라이브러리별 확인을 추가했다.
- **다크 모드:** '다크 모드를 따라간다'는 주장을 '문서를 열 때의 테마를 따른다'로 좁혔다.
- **과시각화:** 자가 점검 대상을 결론이 추세·구성비·흐름·동작인 절로 좁혔고, 스킬 동작 시험에 과시각화 판정과 재시도 상한을 추가했다.
